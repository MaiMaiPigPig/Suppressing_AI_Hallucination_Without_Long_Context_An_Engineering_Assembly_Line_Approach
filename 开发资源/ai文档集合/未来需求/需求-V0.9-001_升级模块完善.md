# 需求-v0.9-001_升级模块完善

## 一、目标

完善 `upgrade/` 角色升级模块，使其达到与 `creation/` 同等的代码卫生标准和可维护性。

## 二、前置依赖

- [ ] v0.8 全部任务已完成并验收通过

## 三、范围

### 包含
- `dnd_5r/upgrade/` 下所有文件
- `upgrade/` 与 `creation/`、`core/` 的共用逻辑梳理

### 不包含
- `creation/` 车卡流程（除非需要提取共用逻辑到 `core/`）
- 后端 API
- 其他功能模块

## 四、当前问题

`upgrade/` 模块在 v0.4/v0.5 期间被标记为"半成品，暂不处理"，存在以下技术债务：

| 问题 | 位置 | 说明 |
|------|------|------|
| `escapeHtml()` 重复实现 | `upgrade/core.js` | 与 `utils/html.js` 重复，应改为 import |
| 文件未编号 | `upgrade/steps/` 下 | 未按命名规范加两位数字前缀 |
| 函数名未展开 | 多处 | 仍有 `calcMod`、`getCfgs` 等缩写 |
| 共用逻辑未提取 | `upgrade/` 内部 | 可能与 `creation/` 有重复逻辑，应提取到 `core/` |

## 五、处理方案

1. **代码清理**
   - 删除 `upgrade/core.js` 中的 `escapeHtml()`，改为 `import { escapeHtml } from '../../utils/html.js'`
   - 删除其他与 `utils/`、`core/` 重复的函数

2. **命名规范落地**
   - 步骤文件加编号（`01-level-select.js`、`02-feature-select.js` 等）
   - 函数名展开缩写（`calcMod` → `calculateModifier` 等）
   - 统一概念命名（`character`、`dataCache`、`currentStep` 等）

3. **共用逻辑提取**
   - 梳理 `upgrade/` 与 `creation/` 的共用逻辑
   - 可复用的部分提取到 `core/` 目录
   - `upgrade/` 改为 import 方式引用

4. **功能验证**
   - 升级流程完整跑通
   - 与车卡流程无冲突

## 六、验收标准

- [ ] `upgrade/` 下无重复函数（与 `utils/`、`core/` 对比）
- [ ] 文件已按编号规则重命名
- [ ] 函数名无缩写残留
- [ ] 升级流程完整跑通，无报错
- [ ] 浏览器控制台无报错
- [ ] 所有文件不超过 800 行

## 七、备注

本需求为技术债务偿还，不新增升级系统的业务功能。重点是把现有代码整理到与车卡模块同等的卫生水平。
