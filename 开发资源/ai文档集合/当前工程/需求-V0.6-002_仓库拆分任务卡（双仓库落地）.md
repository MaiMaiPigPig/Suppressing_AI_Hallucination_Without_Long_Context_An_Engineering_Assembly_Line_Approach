# 需求-V0.6-002_仓库拆分任务卡（双仓库落地）

## 〇、背景

原始需求「V0.6-001 仓库拆分（上架工程与开发文档分离）」经人工补充与澄清后，方向收敛为：纯本地、无远程、无历史提交、拆成两个独立 Git 仓库，拆分完成后废弃原单一仓库。

## 一、目标

将当前单一 Git 仓库拆分为两个独立本地仓库：

- **仓库1（应用工程）**：仅 `TableChronicle/` 应用本体，纯本地仓库
- **仓库2（开发文档与工具链）**：TableChronicle 之外的全部开发资产，纯本地仓库

## 二、验收准绳（人工裁定，以本组为准）

> **① 仓库正常保存　② 不影响程序运行　③ 不影响程序外的东西对程序进行维护、检查**

其中「程序外的东西」特指仓库2 中的可复用工具：`csv转json.py`（数据更新）、`测试脚本/车卡_回归测试.py`（回归检查）、ESLint 工具链（代码检查）。
即拆分后需保持：数据生产、回归测试、代码检查三条链路仍可作用于仓库1 程序。

## 三、前置依赖

- [x] V0.5 全部任务已完成并验收通过（2026-10-02 人工裁定：V0.5 核心需求已验收，剩余两项代码层面遗留——移除特性选择步骤、步骤编号修正——延后至 V0.8 收尾处理，不阻塞 V0.6 仓库拆分）

## 四、范围

### 仓库1（应用工程）
- `TableChronicle/` 全部内容（应用可运行本体）
- 仓库1专用 `.gitignore`

### 仓库2（开发文档与工具链）
- `开发资源/` 全部内容（文档、schema、数据工具 `csv转json.py` 等）
- `测试脚本/` 全部内容
- 工具链配置：`package.json`、`package-lock.json`、`eslint.config.mjs`、`jsconfig.json`
- 仓库2专用 `.gitignore`

### 不进任一仓库 / 不纳入
- `node_modules/`、`.pytest_cache/`、`__pycache__/`（gitignore）
- `.vscode/`（本地编辑器配置，均不纳入）
- 根目录旧 `.git`（废弃，卡C 确认后删除）

## 五、任务卡

### 卡 A · 建立应用工程仓库（仓库1）

**改动**：以 `TableChronicle/` 为根 `git init` → 编写仓库1专用 `.gitignore` → 首次提交。

**验收标准**：
- [ ] A1 仓库1 为独立 git 仓库，可正常 add / commit / 保存
- [ ] A2 程序独立运行正常：启动 `app.py`（Flask 5001）首页、车卡页、数据加载正常
- [ ] A3 对应验收准绳③：仓库2 的回归测试脚本仍能连上本程序执行（详见卡 B）

### 卡 B · 建立开发文档与工具链仓库（仓库2）

**改动**：以开发资产目录为根 `git init` → 编写专用 `.gitignore` → 首次提交。

**验收标准**：
- [ ] B1 仓库2 为独立 git 仓库，可正常 add / commit / 保存
- [ ] B2 `csv转json.py` 仍能产出 JSON 供仓库1 更新数据
- [ ] B3 `测试脚本/` 回归测试仍能对仓库1 程序执行
- [ ] B4 仓库1 代码仍能被仓库2 的 ESLint 工具链检查

### 卡 C · 废弃旧单一仓库（依赖 A、B 验收通过后）

**执行原则**：先建后验再删——卡A、卡B 两个新仓库已建好且全部验收通过后，才允许执行删除。

**改动（破坏性）**：删除根目录旧 `.git`，保留两个新仓库。

**回滚方案**：在删除旧 `.git` 前，确保仓库1和仓库2已经各自独立运行且验收全部通过。如果删除后发现问题，旧仓库文件（除 `.git` 外）未被破坏，可随时重新 `git init`。

**验收标准**：
- [ ] C1 原根目录不再是 git 仓库
- [ ] C2 仓库1、仓库2 各自独立正常，且准绳②③ 两条链路（运行 / 维护检查）实测通过
- [ ] C3 如卡C 执行后发现问题，旧仓库文件仍完整可用，可回退到原始状态重新来过
