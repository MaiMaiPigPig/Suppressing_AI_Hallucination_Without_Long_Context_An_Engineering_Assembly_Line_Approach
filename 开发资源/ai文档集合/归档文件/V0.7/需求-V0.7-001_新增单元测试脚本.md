# 需求 V0.7-001：新增单元测试脚本

## 需求背景

`dnd_5r` 前端代码经过多个版本迭代，核心工具函数（`utils/`）、数据处理逻辑（`core/data/`）和规则引擎（`handlers/`）已相对稳定，但缺乏自动化测试覆盖。随着功能增加，手动回归成本上升，需要建立单元测试体系保障核心逻辑的正确性。

## 目标

1. 搭建可运行的单元测试框架
2. 为纯函数模块编写测试用例
3. 建立持续运行的测试基线

## 范围

### 纳入测试

| 模块 | 文件 | 说明 |
|------|------|------|
| 工具函数 | `utils/html.js` | `escapeHtml()` |
| 工具函数 | `utils/currency.js` | `parsePrice()` / `toCP()` / `formatCurrency()` |
| 常量定义 | `core/constants/character-constants.js` | `ABILITY_NAMES` / `STEP_DATA_FIELDS` / `UPGRADE_STEP_DATA_FIELDS` |
| 字典映射 | `core/data/dictionary.js` | `translateDamageType()` / `translateProperties()` / `getSchoolMap()`¹ / `getFeatTypeMap()`¹ / `getWeaponTypeMap()`¹ |

> ¹ `getSchoolMap()` / `getFeatTypeMap()` / `getWeaponTypeMap()` 为任务 A 新增函数，当前代码不存在，需任务 A 完成后方可测试。
| 数据缓存 | `core/data/cache.js` | `setDataCache()` / `applyDLCFilter()` |
| 占位符处理 | `core/data/loader.js` | `replacePlaceholdersInText()` |
| 规则引擎 | `handlers/basic.js` | `parse()` |
| 规则引擎 | `handlers/choose.js` | `splitArgs()` |
| 规则引擎 | `handlers/filter.js` | `parse()` |
| 规则引擎 | `handlers/index.js` | `parseRule()` |

### 不纳入测试

| 模块 | 原因 |
|------|------|
| DOM 操作 | 需要浏览器环境，不属于单元测试范围 |
| 全局状态依赖 | `character-model.js` / `character-state.js` 依赖可变全局状态，测试复杂度高 |
| `upgrade/` 模块 | 升级流程涉及多步骤状态流转，属于集成测试范围 |
| `creation/steps/` UI 层 | 步骤文件包含大量 DOM 操作和事件绑定 |

## 前置依赖

**任务-V0.7-001-A**：`dictionary.js` 消除 `window` 依赖（P0 阻塞）

当前 `dictionary.js` 通过 `window.DAMAGE_TYPE_MAP` / `window.PROPERTY_MAP` 读取映射表，测试环境没有 `window`，无法运行。需先完成任务 A 的 `initDictionaryMaps(cache)` 改造。

## 测试框架

**选型：Vitest**

理由：
- ESM 原生支持，无需 Babel 转换
- 零配置，与项目现有 ESM 模块兼容
- 安装简单：`npm install -D vitest`
- 与 Vite 生态一致，未来如需构建工具迁移成本低

## 测试策略

### 1. 纯函数测试（优先级 P1）

输入确定 → 输出确定，无外部依赖。

| 函数 | 说明 |
|------|------|
| `escapeHtml(text)` | 特殊字符转义（`<`, `>`, `&`, `"`） |
| `parsePrice(str)` | 各种货币格式解析（`5gp`, `1sp 2cp`, `0.5gp`） |
| `toCP(price)` | 换算为铜币 |
| `formatCurrency(cp)` | 格式化输出 |
| `translateDamageType(type)` | 英文伤害类型 → 中文名，查不到原样返回 |
| `translateProperties(props)` | 武器属性 ID → 中文名，支持数组/字符串输入 |
| `getSchoolMap()`¹ | 返回 ID → 法术学派名称映射 |
| `getFeatTypeMap()`¹ | 返回 ID → 专长类型名称映射 |
| `getWeaponTypeMap()`¹ | 返回 ID → 武器类型名称映射 |
| `replacePlaceholdersInText(text, item)` | 占位符替换（`%x%` / `%y%` 等） |

> ¹ `getSchoolMap()` / `getFeatTypeMap()` / `getWeaponTypeMap()` 为任务 A 新增函数，当前代码不存在，需任务 A 完成后方可测试。

### 2. 数据缓存测试（优先级 P1）

| 函数 | 说明 |
|------|------|
| `setDataCache(data)` | 数据写入后 `getDataCache()` 可读取 |
| `applyDLCFilter(dlcList)` | 按 DLC 过滤后数据范围正确 |

### 3. 规则引擎测试（优先级 P1）

验证"规则字符串 → 结构化对象"的翻译是否正确。

| 函数 | 说明 |
|------|------|
| `handlers.basic.parse(rule)` | 基础值规则（`hp`, `AbilityModifiers`, `Proficiency`） |
| `handlers.choose.splitArgs(str)` | 参数拆分（逗号分隔、嵌套括号） |
| `handlers.filter.parse(rule)` | 筛选规则解析 |
| `handlers.index.parseRule(rule)` | 路由分发，选择正确的 handler |
