## 缺陷 1：`prerequisite()` 剥离顺序错误 — 多条件时等级检查照样失效（🔴 阻塞）

**位置**：四节「阶段 3」，步骤 A，`checkPrerequisite` 改写代码。

当前设计流程：

```javascript
// 第 1 步：对全量字符串剥离 prerequisite()
var outerMatch = inner.match(/^prerequisite\((.+)\)$/i);
if (outerMatch) { inner = outerMatch[1]; }

// 第 2 步：拆分条件
var conditions = splitTopLevel(inner, ',');
```

**问题**：正则带 `^...$` 锚点，要求**整串**被 `prerequisite(...)` 包裹。多条件 prerequisite 如：

```
prerequisite(lv:class(11)=2),spells(class=11, lv=0, dice=1)+1
prerequisite(lv:class(11)=5),class_extra(id=33)
```

`/^prerequisite\((.+)\)$/` 不匹配——`)$` 后面还有 `,spells(...)+1`。于是跳过剥离，直接进入 `splitTopLevel`：

- 条件 1：`prerequisite(lv:class(11)=2)` → `lv` 正则被 `prerequisite(` 前缀挡住 **❌**
- 条件 2：`spells(class=11, lv=0, dice=1)+1` → spells 正则匹配 ✅

**结果**：多条件场景下，等级检查仍然失效。`class_extra.json` 中 9 条含 `spells` 或 `class_extra` 的多条件魔能祈唤，其等级先决条件在修复后依然不会生效。开发按设计修完跑测试会发现"等级 1 仍能选择星移步法"——因为等级检查根本没跑。

**正确顺序**：**先 `splitTopLevel`，再对每个子条件单独剥 `prerequisite()`**：

```javascript
var conditions = splitTopLevel(inner, ',');
for (var ci = 0; ci < conditions.length; ci++) {
    var cond = conditions[ci].trim();
    if (!cond) continue;

    // 每个子条件单独剥 prerequisite()
    var m = cond.match(/^prerequisite\((.+)\)$/i);
    if (m) cond = m[1];

    // 然后正则匹配 lv:class / spells / class_extra ...
}
```

这样 `prerequisite(lv:class(11)=2)` → 剥后 `lv:class(11)=2` → lv 正则命中 ✅。

**同样问题存在于**：同节的步骤 B，`translatePrereq` 的改写代码，顺序需同步修正。

## 缺陷 2：`spells()` 正则捕获 `+N` 数量要求但未使用（🟡 次要）

**位置**：四节「阶段 3」，步骤 A，spells 正则及检查逻辑。

正则捕获了尾部的数量要求：

```javascript
(?:\+\s*(\d+))?  // 捕获 +N
```

但检查逻辑只用 `selectedSpells.some()` — 找到 1 个就通过，未使用捕获的数量值。当前数据中 `+1` 均满足（因为该条件下最多只会有一个匹配法术），不算实际 bug。

**风险**：未来数据若出现 `spells(...)+2`（需要 ≥2 道此类法术），检查会误通过。

**建议**：加 `count >= required` 判断，或至少注释注明当前 `+1` 为事实上限。

## 缺陷 3：`splitTopLevel` 在 renderer.js 和 collector.js 各写一份（🟡 次要）

**位置**：四节「阶段 3」，步骤 C「代码复用注意事项」。

设计决定两个文件各自内联一份 `splitTopLevel`，不 export 不 import。约 12 行代码，不算大问题。但两份副本长期维护可能漂移——一个文件改了逻辑，另一个忘了同步。

**建议**（非强制）：如果后续步骤数增多，考虑抽到 `core/` 下共享。

## 缺陷 4：阶段 5 PDF 新模块缺少 CSS 定义清单（🟡 次要）

**位置**：六节「阶段 5」，步骤 B/C/D。

代码示例有了（技能熟练 HTML 拼接、装备列表），但 CSS 只写了一行：

> 同时补充对应的 CSS（内联在 PDF 导出 `<style>` 块中）

没列出具体类名和样式。新引入的 `.pdf-skill-list`、`.pdf-skill-item`、`.pdf-equip-list`、`.pdf-equip-item` 等类名如果在 `<style>` 块中没有定义，导出的 PDF 这些模块会无样式裸奔。

**建议**：补充 CSS 类名清单，或至少注明"参照 16-export.js 现有 `.pdf-*` 样式风格编写"。
