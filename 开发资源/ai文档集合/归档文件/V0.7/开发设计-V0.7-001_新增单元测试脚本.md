## 六、风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| `15-sheet-renderer.js` 中与 `window.DAMAGE_TYPE_MAP` 耦合的其他全局变量也可能破坏渲染 | 中 | 改动后人工抽查 3 个种族/职业组合，覆盖角色卡头部、法术列表、武器属性标签 |
| `13-review-*.js` 的硬编码字典与 `15-sheet-renderer.js` 不完全一致，替换后可能显示不同 | 中 | 逐文件 diff 对比原硬编码与新 `getXxxMap()` 返回值，确认一致后再替换 |
| `handlers/choose.js` 的 `featLabels`/`wlabels` 可能被 `code-handlers/choose.js` 引用 | 低 | `code-handlers/` 已确认无外部 import，仅自引用；如运行时发现引用，回退该文件改动 |
| 测试中 `dataCache` mock 数据与实际 JSON 结构不一致导致误判 | 中 | mock 数据参照 `dictionary.json` / `weapon_properties.json` 的真实字段结构构建 |
| dictionary 渲染层改动漏改某处导致运行时 `getSchoolMap is not defined` | 中 | 用 grep 全量搜索 `schoolMap`、`featLabels`、`wlabels`、`featTypeNames`、`weaponTypeNames` 关键字，确保每一处都处理完毕 |
| `vitest` ESM 模式下 import `dataCache` / `_fullDataCache` 时与源码的模块级变量共享问题 | 低 | `cache.js` 导出的是模块级变量引用，vitest 可以直接 import 使用，已在缺陷单 1 中确认环境可用 |

### 8.1 `html.test.js` — `escapeHtml()`

| 用例 | 输入 | 期望 |
|------|------|------|
| 正常：`<`、`>`、`&`、`"`、`'` | `<script>` | `&lt;script&gt;` |
| 正常：已转义不二次转义 | `&amp;` | `&amp;amp;`（注意 `&` 最先替换） |
| 正常：混合文本 | `a & b "c"` | `a &amp; b &quot;c&quot;` |
| 边界：空字符串 | `''` | `''` |
| 边界：null | `null` | `''` |
