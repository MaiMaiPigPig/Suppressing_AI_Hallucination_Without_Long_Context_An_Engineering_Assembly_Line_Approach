## 二、功能描述

`dictionary.js` 提供**翻译映射工具函数**，将英文键 / 数字 ID 转换为中文显示文本：

- `translateDamageType(type)` —— 伤害类型英文（如 `cold`）→ 中文（如 `寒冷`）
- `translateProperties(props)` —— 武器属性数字 ID（如 `1,2`）→ 中文名称（如 `弹药、灵巧`）

当前这两个函数通过读取 `window.DAMAGE_TYPE_MAP` 和 `window.PROPERTY_MAP` 全局变量完成翻译。

## 三、数据流向

```
CSV 源数据
    │
    ▼
字典.csv ──→ dictionary.json（伤害类型、法术学派、专长类型、武器类型）
武器特性.csv ──→ weapon_properties.json（武器属性 ID 1-18）
    │
    ▼
loader.js 通过 fetch 加载 JSON → 存入 dataCache
    │
    ▼
【当前】15-sheet-renderer.js 硬编码 window.DAMAGE_TYPE_MAP / window.PROPERTY_MAP
        ↓
      dictionary.js 读 window 全局变量
        ↓
      各渲染模块调用 translateXxx() 显示中文

【目标】loader.js 加载完成后调用 initDictionaryMaps(dataCache)
        ↓
      dictionary.js 从 dataCache 动态构建映射表（模块级变量）
        ↓
      各渲染模块调用 translateXxx() / getXxxMap() 显示中文
```

## 四、改动原因

### 4.1 阻塞测试（主因）

`dictionary.js` 直接依赖 `window` 全局对象：

```js
export function translateDamageType(type) {
    return (window.DAMAGE_TYPE_MAP || {})[type.toLowerCase()] || type;
}
```

单元测试运行在 Node.js 环境，**没有 `window` 对象**，导致测试无法执行。这是需求-V0.7-001（新增单元测试脚本）的 **P0 阻塞项**。

### 4.2 数据不一致

当前 `window.DAMAGE_TYPE_MAP` 和 `window.PROPERTY_MAP` 硬编码在 `15-sheet-renderer.js` 中，与 CSV 源头数据存在多处不一致：

| 问题 | 硬编码值 | CSV 源数据正确值 |
|------|---------|----------------|
| `cold` 翻译 | `冷冻` | `寒冷` |
| 武器属性 ID 6 | `长触及` | `射程` |
| 武器属性 ID 7 | `特殊` | `触及` |
| 武器属性 ID 11-18 | 缺失 | 精通特性（如 `精通：撕裂`） |
| 法术学派 ID 10 | `附魔` | `惑控` |

### 4.3 架构违规

`15-sheet-renderer.js` 属于**展示层**，按架构规范不应包含数据映射逻辑。当前硬编码的 `window.DAMAGE_TYPE_MAP` / `window.PROPERTY_MAP` / `schoolMap` 等属于**公共逻辑层**职责，应下沉到 `core/data/dictionary.js`。

---

## 五、任务描述

将代码中所有硬编码的字典映射改为从 `dictionary.json` / `weapon_properties.json` 动态构建，消除对 `window` 全局对象的依赖，使字典相关函数成为可独立测试的纯函数。

同时修正硬编码数据与 CSV 源头不一致的问题。

## 方案：初始化函数模式（方案 C）

```
loader.js 加载完数据
    │
    ▼
调用 initDictionaryMaps(dataCache) 构建映射
    │
    ▼
dictionary.js 的 translateXxx() 函数使用模块级变量
    │
    ▼
测试环境手动 initDictionaryMaps(mockData) 后调用
```

```js
// 初始化（由 loader.js 调用，测试环境手动调用）
export function initDictionaryMaps(cache) { ... }

// 查询函数（保持原有签名，内部读模块级变量）
export function translateDamageType(type) { ... }
export function translateProperties(props) { ... }

// 新增：供其他模块获取完整映射
export function getSchoolMap() { ... }
export function getFeatTypeMap() { ... }
export function getWeaponTypeMap() { ... }
```

### `initDictionaryMaps(cache)` 构建规则

| 映射变量 | 源数据 | 构建规则 | 空数据回退 |
|----------|--------|----------|------------|
| `DAMAGE_TYPE_MAP` | `cache.dictionary` 中 `id` 47-59 | `name_en.toLowerCase()` → `name` | `{}` |
| `PROPERTY_MAP` | `cache.weaponProperties` 全部 | `id` → `name` | `{}` |
| `SCHOOL_MAP` | `cache.dictionary` 中 `id` 7-14 | `id` → `name` | `{}` |
| `FEAT_TYPE_MAP` | `cache.dictionary` 中 `id` 42-46 | `id` → `name` | `{}` |
| `WEAPON_TYPE_MAP` | `cache.dictionary` 中 `id` 61-65 | `id` → `name` | `{}` |

> 空数据回退策略：`cache.dictionary` 或 `cache.weaponProperties` 为 `undefined` / 空数组时，所有映射置为 `{}`，查询函数返回原值（如 `translateDamageType('cold')` 返回 `'cold'`），避免运行时抛错。
