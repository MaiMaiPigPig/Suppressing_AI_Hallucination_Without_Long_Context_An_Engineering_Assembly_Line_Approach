#### 3.3b 背景页工具熟练显示为原始文本（运行时发现）

**发现**：2026-10-02，背景详情页"工具熟练"栏显示 `tools(type=68)+1` 等原始数据格式，而非翻译后的可读文案。

| 文件                             | 正则（当前）                               | 数据实际格式         |
| -------------------------------- | ------------------------------------------ | -------------------- |

此外 `05-background.js:124` 标签"工匠熟练"为硬编码，对非工匠工具的背景（如赌具 type=68）标签不匹配。

#### 3.3c 熟练表中骰子数值（如 1d6）丢失为 null（数据 pipeline 发现）

**发现**：2026-10-02，`proficiency.json` 中 `type=martial_arts_dice` 的条目 `value` 字段为 `null`，但 CSV 源数据明确有 `1d6`/`1d8`/`1d10`/`1d12`。

**根因**：[csv转json.py:975 parse_value()](file:///f:/跑团工具/开发资源/data/csv转json.py#L975-L992) 只处理两种格式：

- `+10尺` → int + `feet` 单位
- `5` → int

对 `1d6` 这类骰子记法：`int("1d6")` 抛 ValueError → fallthrough 到 `return None, ''` → [apply_field_splitter 1079 行](file:///f:/跑团工具/开发资源/data/csv转json.py#L1079-L1084) 判定为"已解析为空" → JSON 输出 `value: null`。

**波及**：CSV 中所有骰子格式的 value（不限于 martial_arts_dice，任何 `\d+d\d+` 格式）均会丢失。

**处理方案**：

- `parse_value` 中增加骰子格式匹配：`re.match(r'^\d+d\d+$', value)` → 返回 `(value, '')` 保持原字符串
- 重跑 `csv转json.py` 重新生成 `proficiency.json`

#### 3.3d 规则 `X(id=N)` 直接指定 ID 的格式未被任意解析器支持

**发现**：2026-10-02，选择阿斯莫种族 → 特性总览出现法术选择界面，全部法术都列了出来。数据源是 `race_features.json` 中 `spells(id=11)`（应直接获取 11 号法术"光亮术"），但变成了让用户从全部法术中手动选。

**根因**：`handlers/filter.js` 的 `spells(...)` 解析器（第 84 行）只提取 `class`/`lv`/`school`/`dice` 参数，**`id` 参数被静默忽略**。无任何筛选条件 → 展示全部法术供选择。同类问题不仅限于 `spells`，以下是完整的无效映射清单：

| 数据格式 | 出现位置 | 涉及解析器 | 问题 |
|---------|---------|-----------|------|
| `spells(id=N)` | `race_features.json`、`class_features.json`、`feats.json`（~100 处） | `filter.js:84` | `id` 被忽略，展示全部法术供选 |
| `tools(id=N)` | `backgrounds.json`（10+ 处）、`class_features.json` | `filter.js:165`、`08-bonus.js` | `filter.js` 只认 `type=N`；`08-bonus.js` 正则也不匹配（同 3.3b） |
| `skills(id=N)` | `class_features.json`（5+ 处） | `handlers/` | 无解析器支持 `id=N` |
| `languages(id=N)` | `class_features.json`（2 处） | `handlers/` | 无解析器支持 `id=N` |
| `weapons(id=N)` | `classes.json`（2 处） | `handlers/` | 无解析器支持 `id=N` |

**处理方案**（按优先级）：
- `filter.js` spell 解析器：识别 `id=N` → 直接返回指定法术，`needUserSelect: false`
- `filter.js` tool 解析器：补充 `id=N` 支持
- `handlers/` 中补充 `skills(id=N)` / `languages(id=N)` / `weapons(id=N)` 的直接指定支持
- 各解析器遇到未支持的参数时打印 warning，而非静默忽略

- #### 3.3e 角色完成页崩溃：`displayVal.indexOf is not a function`

**发现**：2026-10-03，车卡流程走完进入角色完成页时 crash：
```
16-sheet-main.js:640  Uncaught TypeError: displayVal.indexOf is not a function
```

**根因**：`proficiency-link-resolver.js:46` 返回的 `value` 可能是整数（如 `speed=30`），但 `16-sheet-main.js:640` 对其调用字符串方法 `indexOf`：

```javascript
value: best.value || '0',   // best.value=30(数字) → 返回数字 30，不是字符串

// 16-sheet-main.js:640

```

**处理方案**：`16-sheet-main.js:639` 对 `displayVal` 做类型安全转换：
```javascript
var displayVal = p.value;
if (typeof displayVal !== 'string') {
    displayVal = String(displayVal);
}
```
