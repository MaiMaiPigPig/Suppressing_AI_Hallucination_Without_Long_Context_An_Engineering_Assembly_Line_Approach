### 缺陷 2：测试策略遗漏关键边界情况

**2a. `translateProperties` 的输入格式和 fallback 行为未覆盖**

[代码实际逻辑](file:///f:/跑团工具/TableChronicle/character/dnd_5r/core/data/dictionary.js#L11-L16)：
```javascript
export function translateProperties(props) {
    if (!props || props === '—' || props === '---') return '—';
    const propStr = Array.isArray(props) ? props.join(',') : String(props);
    const parts = propStr.split(',').map(p => p.trim()).filter(Boolean);
    return parts.map(part => {
        return PROPERTY_MAP[part] || `[${part}]`;  // ← fallback 格式
    }).join(', ');
}
```

测试策略表只写"数字 ID 映射 + 保留括号后缀"，遗漏：
- **双输入格式**：数组 `[1, 2, 3]` 和字符串 `"1,2,3"` 两种输入路径
- **fallback 格式**：无效 ID 返回 `[id]`（带方括号），不是空字符串
- **空值处理**：`null` / `'—'` / `'---'` 三种空值均返回 `'—'`

**2b. `replacePlaceholdersInText` 的 mock 复杂度未说明**

[代码实际签名](file:///f:/跑团工具/TableChronicle/character/dnd_5r/core/data/loader.js#L118)：`replacePlaceholdersInText(text, item)`，`item` 必须具有 `rules`、`parts`、属性值（如 `ability_modifier_4`）等字段。测试策略只说"`%x%` / `%y%` 替换逻辑"，未说明 mock item 的最小结构。

**2c. `applyDLCFilter` 的双模块变量依赖未说明**

`applyDLCFilter(dlcList)` 同时读写 `_fullDataCache` 和 `dataCache` 两个模块级变量 [cache.js:60-L70](file:///f:/跑团工具/TableChronicle/character/dnd_5r/core/data/cache.js#L60-L70)。测试需：
- 同时 mock 两个模块变量
- 在测试间调用 `resetCache()` 清理状态
- 覆盖 `FILTERABLE_KEYS` 表和非过滤表的差异化行为

测试策略完全未提及这些。
