## 二、阶段 1：删除步骤9 + 编号顺延（3.1 + 3.2）

### 2.1 09-feature-selection 模块死/活分析结论

经全量追踪，第 9 步（特性选择）当前已是"幽灵步骤"——`renderFeatureSelectionStep()` 入口检测 `hasPendingSelections()`，无待选项时自动跳过、不渲染 UI。但其底层渲染引擎仍被审阅页（步骤 14→13）重度依赖。

#### 保留清单

| 源文件 | 目标文件 | 保留原因 |
|--------|---------|---------|
| `09-feature-selection-utils.js` | `13-review-utils.js` | `addPendingSelectionsFromItem`（审阅收集器用）、`hasPendingSelections`（审阅页判断）、`clearAllPendingSelections`（lifecycle/app 用）、`loadCandidates`/`processChainReferences`/`isSameSelection`（被上述间接调用） |
| `09-feature-selection-renderer.js` | `13-review-renderer.js` | 全部 4 个函数（`getSelectionTitle`、`collectAllAlreadySelectedIds`、`checkPrerequisite`、`renderSelectionItems`）被 `renderFeatureSelectionStep` 内部调用 |
| `09-feature-selection-main.js` | `13-review-engine.js` | `renderFeatureSelectionStep`（审阅页渲染入口）、`confirmAllSelections`（navigation 按钮调度）、`updateAllSelectionsUI` / `showItemDetail`（内部调用） |

#### 删除清单

| 删除项 | 原因 |
|--------|------|
| `09-feature-selection.js`（入口文件） | 仅 re-export，迁移后由 `13-review.js` 替代 |
| utils 中 `schoolMap` | 无外部引用（`16-sheet-renderer.js` 和 `12-spells.js` 各有本地副本） |
| utils 中 `getCurrentPending` | 定义了但无任何调用方 |
| utils 中 `removeCurrentPending` | 同上，死代码 |
| step-router.js `case 9:` 分支 | 步骤9不再存在 |
| step-router.js `import { renderFeatureSelectionStep } from '../steps/09-feature-selection.js'` | 不再需要，替换为 `13-review.js` 入口 |
| character.html 第 9 步进度条项 | 删除整个 `<div class="step-item" data-step="9">` |

#### 保留但需更新的桥接

| 位置 | 用途 | 迁移后状态 |
|------|------|-----------|
| `window._isInFeatureSelection` | 审阅页与 navigation 按钮的桥接状态 | **保留**，navigation.js:219 靠它判断"下一步"该调 `confirmAllSelections()` |
| `window._allSelectionsState` | 审阅页待选状态存储 | **保留**，仍然是审阅页运行时状态 |
| `window._nextStepAfterSelection` | 特性选择完成后跳转目标 | **保留**，审阅页完成后跳到步骤 14（详情） |
| `window._processedFeatIds` | 专长嵌套处理跟踪 | **保留** |

这四个状态变量不因步骤9消失而废弃——审阅页渲染 `renderFeatureSelectionStep(container, 14)` 时仍会设置 `_isInFeatureSelection`、`_nextStepAfterSelection`，navigation 仍然靠它们调度。
