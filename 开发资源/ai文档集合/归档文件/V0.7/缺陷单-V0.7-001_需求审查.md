## 缺陷 1：bridge.js 三个 import 路径指向不存在的文件

**严重程度**：🔴 阻塞

### 问题描述

[upgrade/flow/bridge.js](file:///f:/跑团工具/TableChronicle/character/dnd_5r/upgrade/flow/bridge.js#L26-L32) 第 26-32 行：

```javascript
import { getClassFeatures } from '../../creation/steps/class.js';
import { renderCharacterSheet } from '../../creation/steps/sheet.js';
import { buildSpellDetailHTML } from '../../creation/steps/spells.js';
```

这三个路径在 creation/steps/ 下实际不存在——实际文件为 `03-class.js`、`16-sheet.js`、`12-spells.js`（均带步骤编号前缀）。

bridge.js 通过 [upgrade.html:34](file:///f:/跑团工具/TableChronicle/character/dnd_5r/upgrade/upgrade.html#L34) 以 `<script type="module">` 加载。ES Module 的 import 是静态解析的，路径不存在会导致整个模块加载失败。`window.getClassFeatures`、`window.renderCharacterSheet`、`window.buildSpellDetailHTML` 全部为 `undefined`。

需求验收标准第四条只说"核对一致"，未明确是否要修复。

### 影响

升级页大概率已挂——bridge.js 模块加载失败后，升级功能依赖的几个全局函数全部未定义。车卡回归测试（18/18 通过）只测创建流程，不覆盖升级页面，此问题未被任何自动化测试发现。

### 证据

```powershell
Get-ChildItem creation/steps -Name | findstr "^class\.js$ ^sheet\.js$ ^spells\.js$"
# exit code 1（无匹配，三文件不存在）
```

### 建议

将三个 import 路径改为实际文件名：

- `'../../creation/steps/class.js'` → `'../../creation/steps/03-class.js'`
- `'../../creation/steps/sheet.js'` → `'../../creation/steps/16-sheet.js'`
- `'../../creation/steps/spells.js'` → `'../../creation/steps/12-spells.js'`

或在需求中明确：V0.8 执行后步骤编号会变，bridge.js 的路径需一并同步更新到最终文件名。

## 缺陷 2：3.1 遗漏 `09-feature-selection` 的 3 个关联文件

**严重程度**：🟠 中等

### 问题描述

需求 3.1 写"移除特性选择步骤及其文件 `09-feature-selection.js`"，但当前 `creation/steps/` 下实际存在 4 个相关文件：

```
09-feature-selection.js
09-feature-selection-main.js
09-feature-selection-renderer.js
09-feature-selection-utils.js
```

只删 `09-feature-selection.js` 会残留另外三个死文件 + 可能被其他步骤 import 导致的引用断裂。

### 建议

改为"移除 `09-feature-selection.js` 及其关联文件（`-main.js`、`-renderer.js`、`-utils.js`）"。
