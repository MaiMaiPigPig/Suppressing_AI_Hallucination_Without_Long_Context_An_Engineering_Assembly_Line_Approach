# 缺陷单-v0.4-003：动态 import 并发防护缺失

**关联设计**：设计-v0.4-002-C_creation流程层拆分.md  
**审查日期**：2026-09-28  
**审查依据**：测试生产准则 流程分支 2 — 攻击维度：并发

---

## 问题描述

### 现状

002-C 的 step-router.js 使用动态 `import()` 异步加载步骤模块：

```javascript
const STEP_RENDERERS = {
  1: { render: () => import('../steps/race.js').then(m => m.renderRaceStep) },
  // ...
};

export async function renderStep(step, container) {
  const renderFn = await STEP_RENDERERS[step].render();
  renderFn(container);
}
```

### 风险

用户快速连点"下一步"时，可能触发多次 `renderStep`，导致：
- 前后两个步骤的渲染交错执行（前一步尚未渲染完、后一步已经开始）
- UI 短暂闪烁或内容覆盖
- 极端情况下显示的是前一步的内容但导航状态已跳到后一步

### 设计现状

此问题在设计文档中无覆盖。开发反馈认为并发防护属于"编码实现细节，不属于设计文档职责范围"。

---

## 影响范围

- `creation/flow/step-router.js` — renderStep 入口
- `creation/flow/navigation.js` — nextStep / prevStep / goToStep 调用方
- `upgrade/flow/step-router.js` — 同样使用动态 import（如果 upgrade 也采用此模式）

---

## 建议

设计层面不需要写 lock 或 debounce 的具体实现代码，但应明确行为契约：

> 步骤切换期间（上一次 renderStep 未完成时），重复调用 renderStep 的行为是什么？
> - 方案 A：排队执行（上一次完成后再执行下一次）
> - 方案 B：丢弃新请求（上一次未完成时忽略后续调用）
> - 方案 C：中断上一次、立即执行新的

设计文档只需选定方案并标注行为契约，具体编码实现由开发决定。
