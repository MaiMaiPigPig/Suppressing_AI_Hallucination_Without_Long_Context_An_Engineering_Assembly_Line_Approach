### 2.5 顺带修掉的真实缺陷

| 问题 | 说明 |
|------|------|
| `handlers/{attribute,choose,feat-require,table-map}.js` 仍用已废弃的 `handlers.xxx.YYY` 命名空间 | `window.handlers` 只挂了 `processItemRules`/`parseRule`，`handlers.attribute.ABILITY_ID_MAP` 等**运行必抛 TypeError**。5 处改为直接引用模块内符号 |
| `selection-modal.js` 两处正则写成 `(?:\s*+\s*(\d+))?` | 应为 `(?:\s*\+\s*(\d+))?`（匹配 `+N`）。`\s*+` 是占有量词，在未支持该语法的浏览器上是**模块级语法错误**，会让整个车卡模块图加载失败；即使支持，`tool(type=X)+N` 也会被静默当成数量 1 |
| `spells.js` 桥接 `window.getAbilityNameById` 会覆盖 `data-query.js` 的同名实现 | 两者语义不同（后者带 `'—'` 兜底，升级侧依赖它），已去掉该桥接 |
| `utils/currency.js` 的 `getCurrencyCP`/`deductCurrency` 是死代码且引用了已不存在的全局 `character` | 删除（`navigation.js` 有自己的同名实现） |
| `step-router.js` 的 `isSpellStepSkippable` 依赖 `typeof getSpellDataFromProficiency === 'function'` | 模块作用域下该判断恒为 false，永远走已失效的 `LEVEL1_BASE_SPELLS` 分支（缺陷 10）。改为正式 import |
| `app.js`/`lifecycle.js` 对 `clearAllPendingSelections`、`selection-modal.js` 对 `renderStep`/`getCurrentStep` 的 `typeof` 兜底 | 静态 import 后恒真，改为直接调用并补 import |

### 2.6 工程配置

### 7.1 本轮修复内容

| 缺陷 | 处理 |
|------|------|

**根因**：这些函数迁移前是全局函数，转 ES Module 后不再自动成为全局，而动态 HTML 的 `onclick`

没验证交互，因此漏掉了这一整类问题。已在本轮补上。

### 7.2 新增的验证手段

原车卡冒烟测试只跑 `renderStep(1..17)`，抓不到内联事件处理器缺失。本轮补了两道：

1. **静态校核**：扫描全部动态 HTML 的内联事件属性，校验每个被调函数都有 window 桥接。
   （首版提取器用 `[^"']*` 匹配属性值，遇到 `onclick="${cond ? '' : \`fn()\`}"` 这类嵌套模板串会提前截断
   而漏报，已改为按 `${}` / 反引号深度扫描。）
2. **运行时校验**：真实加载模块图后逐一确认 37 个内联处理器确实挂在 `window` 上
   —— 静态扫描只能证明源码里有 `window.x = x`，这一步证明模块求值时它真的执行了。
