## 一、设计目标

16 个步骤文件的 `renderXxxStep()` 函数当前是全局定义，step-router.js 无法 import。改造为 ES Module 后，step-router.js 通过 `import` 获取渲染函数，步骤文件不再依赖全局作用域获取 `dataCache` 和 `character`。

---

## 二、设计方案

### 2.1 导入方式：静态 import（开发决策）

不采用动态 `import()`，采用静态 `import`。理由：

- 无并发问题（不需要中断/排队/丢弃机制）
- 依赖关系显式声明，后续功能可直接 `import` 复用
- 16 个文件总计不到两万行，一次性加载对本地工具无影响

### 2.2 步骤文件改造模式

每个步骤文件做三处改动：

```javascript
// === 改造前（race.js 为例）===
// （顶部无 import）
function renderRaceStep(container) { ... }
function renderSubraceStep(container) { ... }
function selectRace(raceId) { ... }

// === 改造后 ===
// 1. 顶部加 import
import { dataCache } from '../../core/data/cache.js';
import { character } from '../../core/state/character-model.js';

// 2. render 函数加 export
export function renderRaceStep(container) { ... }
export function renderSubraceStep(container) { ... }

// 3. onclick 函数挂 window（不 export，保持 HTML onclick 正常工作）
function selectRace(raceId) { ... }
window.selectRace = selectRace;
```

**原则**：
- 只 `export` render 函数（被 step-router.js import）
- onclick 函数和内部辅助函数挂 `window`，不改函数体
- 不改函数签名、不改内部逻辑

## 四、特殊处理

### 4.1 race.js 同时导出两个 render 函数

`renderRaceStep` 和 `renderSubraceStep` 都在 race.js 中。step-router.js 从同一文件 import 两者：

```javascript
import { renderRaceStep, renderSubraceStep } from '../steps/race.js';
```

### 4.2 feature-selection.js 超 800 行

当前 1861 行，远超规范限制。改造时仅加 `export` + `import`，**不拆分**。拆分方案待补需求单 #1 落地后单独执行。

### 4.3 window 桥接与模块导入互不冲突

步骤文件的 onclick 函数挂 `window`，render 函数走 `export`，两者独立：

- `step-router.js` 通过 `import { renderRaceStep }` 获取渲染函数 → 进入模块作用域
- HTML 中的 `<div onclick="selectRace(1)">` 通过 `window.selectRace` 获取回调 → 进入全局作用域
- 两条路径不互斥、不冲突

### 4.4 共享函数 toggleUnbind（skill.js 单一定义）

`toggleUnbind` 被 bonus.js、skill.js、feat.js 三个文件通过 onclick 调用，但**只在 skill.js 中定义**。

改造后：
- skill.js 在窗口桥接中挂 `window.toggleUnbind = toggleUnbind;`
- bonus.js 和 feat.js 不定义也不桥接 `toggleUnbind`——静态 import 保证所有模块同时加载，skill.js 的 `window.toggleUnbind` 先就绪
- 三个文件的 HTML onclick 统一调用 `window.toggleUnbind`
