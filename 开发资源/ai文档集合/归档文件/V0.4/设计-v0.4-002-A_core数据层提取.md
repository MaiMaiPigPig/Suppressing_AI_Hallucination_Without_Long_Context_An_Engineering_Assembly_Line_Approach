## 一、模块划分

### 1.1 文件结构

```
core/data/
├── loader.js      # 数据加载 + 占位符预处理
├── cache.js       # 运行时缓存管理
└── indexes.js     # 数据索引构建
```

### 1.2 职责边界

| 文件 | 职责 | 不职责 |
|------|------|--------|
| loader.js | 加载 JSON 文件、预处理占位符 | 不管理缓存状态 |
| cache.js | 存储 dataCache/_fullDataCache、提供重置接口 | 不加载数据 |
| indexes.js | 构建查询索引 | 不直接操作缓存变量 |

## 六、异常处理策略

| 接口 | 异常场景 | 处理策略 |
|------|----------|----------|
| `loadData(dlcList)` | JSON 文件 404/网络错误 | 抛出错误，由调用方（lifecycle.js）捕获并显示"数据加载失败"提示 |
| `loadData(dlcList)` | dlcList 为空数组 | 允许加载，只加载基础数据（无 DLC） |
| `applyDLCFilter(dlcList)` | dlcList 为空数组 | dataCache 置为空对象（除非过滤表外） |
| `preprocessAllPlaceholders(data)` | 占位符指向不存在的字段 | 保持原样不替换，记录 warn |
| `buildDataIndexes()` | dataCache 为空 | 正常执行（索引为空），不报错 |

## 七、风险与回滚

| 风险 | 应对方案 |
|------|----------|
| 路径错误导致 404 | 检查相对路径：`creation/` → `../core/data/`，`upgrade/` → `../core/data/` |
| applyDLCFilter 两处实现不同 | 对比 character.js:45 和 upgrade.js:114 的实现差异，取并集或确认行为一致 |
| loadData 异步时序问题 | 保持 async/await 调用方式不变，确保 app.js 中 await loadData() |

**回滚方案**：保留原 character.js 和 upgrade.js 的备份，出现问题时恢复全局变量定义。
