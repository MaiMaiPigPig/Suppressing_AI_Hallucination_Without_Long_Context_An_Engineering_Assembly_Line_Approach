## 一、模块划分

### 1.1 当前架构问题

- `handlers` 用 `var handlers = {}` 声明，依赖浏览器全局作用域
- `character.html` 通过 `creation/character.js` 定义 handlers
- `upgrade.html` 通过内联 `<script>var handlers = {};</script>` 定义
- 16 个 handlers/*.js 使用扩展模式：`handlers.xxx = handlers.xxx || {}; handlers.xxx.parse = function(...)`
- `handlers/data-query.js` 定义全局函数，不走 handlers 命名空间

### 1.2 目标架构

**方案 A：注册表模式（推荐）**

```
handlers/
├── basic.js              # export function parse(...)
├── attribute.js          # export function parse(...)
├── ...                   # 其他 handler 同理
├── index.js              # 注册表：import 所有 handler，统一调度
└── data-query.js         # export function buildDataIndexes(...)
```

**方案 B：保持扩展模式但模块内注册**

```
handlers/
├── basic.js              # import { handlers } from './index.js'; handlers.basic = {parse: ...}
├── ...
└── index.js              # export let handlers = {};
```

**v0.4 选择**：方案 A（注册表模式），原因：
- 符合 ES Module 规范
- 便于静态分析和 tree-shaking
- 调用方只需 import 注册表，无需关心具体 handler

## 二、接口设计

### 2.1 handlers/index.js（注册表）

```javascript
// 导入所有 handler 子模块
import * as basic from './basic.js';
import * as attribute from './attribute.js';
import * as level from './level.js';
import * as filter from './filter.js';
import * as operation from './operation.js';
import * as proficiency from './proficiency.js';
import * as chain from './chain.js';
import * as selection from './selection.js';
import * as resource from './resource.js';
import * as choose from './choose.js';
import * as special from './special.js';
import * as tableMap from './table-map.js';
import * as featRequire from './feat-require.js';
import * as weaponMastery from './weapon-mastery.js';

/**
 * Handler 注册表
 * 键名对应规则中的 handler 类型
 */
export const handlerRegistry = {
  basic,
  attribute,
  level,
  filter,
  operation,
  proficiency,
  chain,
  selection,
  resource,
  choose,
  special,
  tableMap,
  featRequire,
  weaponMastery,
};

/**
 * 解析单条规则
 * 原位置：handlers/index.js（原实现）
 * 
 * @param {Object} rule - 规则对象，格式：{handler: 'basic', ...}
 * @param {Object} character - 角色对象
 * @param {Object} options - 解析选项
 * @returns {Object} 解析结果
 */
export function parseRule(rule, character, options) {
  const handler = handlerRegistry[rule.handler];
  if (!handler || !handler.parse) {
    console.warn(`未知 handler: ${rule.handler}`);
    return null;
  }
  return handler.parse(rule, character, options);
}

/**
 * 处理物品规则列表
 * 原位置：handlers/index.js（原实现）
 * 
 * @param {Object} item - 物品对象
 * @param {Object} character - 角色对象
 * @param {Object} options - 解析选项
 */
export function processItemRules(item, character, options) {
  if (!item.rules) return;
  
  for (const rule of item.rules) {
    parseRule(rule, character, options);
  }
}
```

## 三、HTML 加载方式调整

### 3.1 character.html

**改造前**：
```html
<script src="character.js"></script>  <!-- 定义 var handlers = {} -->
<script src="handlers/basic.js"></script>
<script src="handlers/attribute.js"></script>
<!-- ... 16 个 handler 文件 -->
<script src="handlers/index.js"></script>
```

**改造后（保留 script 标签但统一声明）**：
```html
<!-- 方案：在 app.js 中统一 import handlers -->
<script type="module" src="app.js"></script>

<!-- app.js 内部： -->
<!-- import { handlerRegistry, parseRule } from '../handlers/index.js'; -->
```

**v0.4 边界**：如页面层不改 ES Module，则：
1. 删除 `character.js` 中的 `var handlers = {}`
2. 在 HTML 中保留 `<script>var handlers = {};</script>`（与 upgrade.html 一致）
3. handlers/*.js 仍按原顺序加载
4. 但 `handlers/index.js` 改为注册表模式，为后续完全模块化做准备

### 3.2 upgrade.html


## 六、风险与回滚

| 风险 | 应对方案 |
|------|----------|
| 16 个 handler 文件改造遗漏 | 按清单逐个检查，逐个验证 |
| handler.parse 函数签名不一致 | 对比改造前后的函数参数，确保一致 |
| 全局 handlers 对象被其他代码依赖 | 全局搜索 `handlers\.`，确认所有引用点已处理 |
| data-query.js 的全局函数被外部调用 | 全局搜索 `findItemSourceTable\|collectChainedRaceFeatures`，确认所有调用点已改 import |
| code-handlers/ 未处理 | 见下方「code-handlers 处理策略」 |
| 注册表模式性能问题 | handlerRegistry 是静态对象，无运行时性能损失 |

## 七、code-handlers 处理策略

### 7.1 现状

项目存在两个 handler 目录：
- `handlers/` — 16 个规则解析 handler（basic, attribute, level, filter, ...）
- `code-handlers/` — 代码生成相关 handler（代码片段处理）

### 7.2 v0.4 处理方案

`code-handlers/` **暂不迁移**，原因：
1. 与 `handlers/` 职责不同：code-handlers 处理代码生成，不处理规则解析
2. 当前无 ES Module 改造需求（无全局变量污染问题）
3. 调用方单一，仅在导出功能中使用

**技术债记录**：
| 问题 | 位置 | 建议处理版本 |
|------|------|-------------|
| code-handlers/ 未模块化 | code-handlers/*.js | v0.5 |

### 7.3 异常处理策略

| 接口 | 异常场景 | 处理策略 |
|------|----------|----------|
| `parseRule(rule, character, options)` | rule.handler 不存在 | 返回 null，console.warn 提示 |
| `parseRule(rule, character, options)` | handler.parse 不存在 | 返回 null，console.warn 提示 |
| `processItemRules(item, character, options)` | item.rules 不存在 | 静默返回，不报错 |
| handler 子模块 parse | 规则格式错误 | 抛出 Error，由 parseRule 捕获并返回 null |
