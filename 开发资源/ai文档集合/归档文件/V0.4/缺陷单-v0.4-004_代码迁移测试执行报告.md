## 缺陷详情

### 缺陷 1（阻塞）：步骤文件未加载

**位置**：
- [character.html:L313-L316](file:///f:/跑团工具/TableChronicle/character/dnd_5r/creation/character.html#L313-L316)
- [step-router.js:L14-L46](file:///f:/跑团工具/TableChronicle/character/dnd_5r/creation/flow/step-router.js#L14-L46)

**现象**：character.html 仅加载 3 个模块脚本（handlers/index.js、handlers/data-query.js、app.js）。app.js → navigation.js → step-router.js → 调用 `renderRaceStep(c)` 等 17 个函数。

这些函数定义在 `creation/steps/*.js` 中，但 step-router.js 没有 import 它们，character.html 也没有以 script 标签加载它们。在 ES Module 作用域中，这些函数全部为 `undefined`。

**结果**：点击"开始创建角色"后 `ReferenceError: renderRaceStep is not defined`，车卡流程直接崩。

### 缺陷 5（🟢 低，降级并入缺陷 2）：动态 import 未实现

**位置**：[step-router.js:L1-L46](file:///f:/跑团工具/TableChronicle/character/dnd_5r/creation/flow/step-router.js#L1-L46)

**现象**：设计 002-C 要求使用动态 `import()` 按需加载步骤模块，实际实现用了硬编码 switch-case + 直接函数调用，且无任何 import 语句。

```javascript

  1: { render: () => import('../steps/race.js').then(m => m.renderRaceStep) }
};

// 实际代码
```

**❌ 驳回理由**（开发 AI，2026-09-29）：

1. **根因是缺陷 2，不是独立缺陷**：17 个步骤文件 0 export。在没有 export 的情况下，动态 import 和静态 import 的结果相同——都拿不到函数。修了缺陷 2 之后，是用动态 import 还是静态 import 只是实现方式的选择，不影响功能。
2. **严重度虚高**：标为"严重"不合理。缺陷本身是同一根因的伴生问题，应随缺陷 2 一并处理，不单独追踪。降为**低**。

**✅ 测试核验**（2026-09-29）：接受。defect 2 解决前动态/静态 import 均不可用。缺陷 5 降为 🟢 低，并入缺陷 2 修复范围，等步骤 ES Module 化时统一决定路由方式。

### 缺陷 14（🟡 中）：step-router 无 @throws 文档

**位置**：[step-router.js](file:///f:/跑团工具/TableChronicle/character/dnd_5r/creation/flow/step-router.js)

**❌ 驳回理由**（开发 AI，2026-09-29）：

1. **非功能缺陷**：`@throws` 是 JSDoc 文档注释，缺失不影响编译、不影响运行、不影响用户可见行为。

3. **结论**：驳回缺陷身份，降为代码清理提醒（见 002-I 子文档）。

**✅ 测试核验**（2026-09-29）：接受降级但不驳回身份。设计 002-C 有明确 @throws 要求，代码确实缺失——内存事实存在。严重度从 🟡 中降为 🟢 低，随代码清理阶段处理，不单独追踪。

### 缺陷 28（🟠 严重）：nextBtn 双重事件处理器导致步骤验证误报

**位置**：
- [app.js:62](file:///F:/跑团工具/TableChronicle/character/dnd_5r/creation/app.js#L62)（旧）`document.getElementById('nextBtn').addEventListener('click', nextStep);`
- [navigation.js:218](file:///F:/跑团工具/TableChronicle/character/dnd_5r/creation/flow/navigation.js#L218) `updateButtons()` 内 `nextBtn.onclick = function() { nextStep(); };`

**现象**：Selenium 端到端测试 `test_02_full_creation_flow` 失败。步骤1选择种族（如兽人）后点击"下一步"，
页面正确跳到步骤3（职业选择页），但同时弹出 `alert('请先选择一个职业')`。

**根因**：`nextBtn` 同时绑定了两个独立的事件处理器：

1. **`addEventListener('click', nextStep)`**：在 [app.js DOMContentLoaded](file:///F:/跑团工具/TableChronicle/character/dnd_5r/creation/app.js#L62) 时注册
2. **`onclick = function() { nextStep(); }`**：在 [navigation.js updateButtons()](file:///F:/跑团工具/TableChronicle/character/dnd_5r/creation/flow/navigation.js#L218) 每次步骤切换时设置

浏览器的 `addEventListener` 和 `onclick` 属性是**互相独立的**——单次点击会同时触发两者。

**执行时序**：
1. 用户点击 nextBtn
2. **第1次 nextStep()**（via addEventListener）：`getCurrentStep()=1` → 验证种族 ✓ → 跳过亚种 → `setCurrentStep(3)` → `renderStep(3)` 渲染职业页 → 返回（无弹窗）
3. **第2次 nextStep()**（via onclick）：`getCurrentStep()=3` → `!character.class` 为 true → `alert('请先选择一个职业')`

**证据（快照）**：
- `step01_pre_next_step1_20260929_230210.txt`：页面在步骤1，兽人已选中
- `step01_blocked_step1_20260929_230210.txt`：页面已跳到步骤3，显示职业网格（野蛮人/吟游诗人等），但测试截获了"请先选择一个职业"弹窗

**影响**：车卡全流程无法跑通。每步点击"下一步"都会被双重调用，第二步的 nextStep() 总是在已跳转后的新步骤上执行验证，必然触发无关步骤的验证弹窗。

**修复方式**（测试已执行，待开发审核）：
- 删除 [app.js:62](file:///F:/跑团工具/TableChronicle/character/dnd_5r/creation/app.js#L62) 的 `addEventListener('click', nextStep)`
- 删除 [app.js:10](file:///F:/跑团工具/TableChronicle/character/dnd_5r/creation/app.js#L10) 的 `nextStep` 导入（不再使用）
- 理由：`updateButtons()` 已完整管理 nextBtn 的 onclick 行为（普通步骤→nextStep、特性选择页→confirmAllSelections、最后一步→goUpgrade），`addEventListener` 作为固定回调会干扰这些动态切换
