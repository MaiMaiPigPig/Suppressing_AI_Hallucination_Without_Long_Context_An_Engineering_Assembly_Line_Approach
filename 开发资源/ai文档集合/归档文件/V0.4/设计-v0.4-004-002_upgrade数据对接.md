## 二、方案：window getter 桥接

### 2.1 为什么不用 ES Module 全量改造

upgrade.js 作为 `defer` 脚本运行，其子步骤文件（spell-update.js、level-select.js）也是 `defer`。如果改为 ES Module：

- 所有 onclick 函数（`goToStep`、`importCharacter`、`goBackToCharacter` 等）需 window 桥接
- 子步骤文件之间 + upgrade.js 之间的全局变量引用（`character`、`dataCache`、`upgradeState`、`currentStep` 等）全部断链
- 改动范围超出数据对接本身，进入 G2-G5 流程层拆分的范畴

**决策**：upgrade.js 保持 `defer`，在 upgrade.html 中插入一个 `<script type="module">` 桥接脚本，把 core/ 模块的 live binding 暴露到 window。

### 2.2 桥接原理

ES Module 的 `import` 绑定是**活的**——模块内部变量重赋值后，import 侧无需刷新即可获取新值。

```javascript
// 桥接脚本
import { dataCache, _fullDataCache } from '../core/data/cache.js';
import { character } from '../core/state/character-model.js';
import { loadData } from '../core/data/loader.js';
import { applyDLCFilter } from '../core/data/cache.js';

// getter：每次访问 window.dataCache 都返回模块的最新值
Object.defineProperty(window, 'dataCache', {
    get: () => dataCache, enumerable: true, configurable: true
});
Object.defineProperty(window, 'character', {
    get: () => character, enumerable: true, configurable: true
});

window.loadUpgradeData = loadData;
window.applyUpgradeDLCFilter = applyDLCFilter;
```

### 2.3 为什么 getter 能在重赋值后工作

`cache.js` 的 `setDataCache(newCache)` 会执行 `dataCache = newCache`（变量重赋值）。`Object.defineProperty` 的 getter 闭包捕获的是 import 的 live binding，而非初始值。变量重赋值后 getter 自动返回新值。

upgrade.js 中所有对 `dataCache` / `character` 的属性读写（如 `dataCache.races`、`character.level = 2`）无需改动。

### 3.2 upgrade.html（+12 行）

```html
<!-- 数据层桥接：把 core/ 模块的 live binding 暴露到 window，供 upgrade.js 的 defer 脚本使用 -->
<script type="module" id="upgrade-data-bridge">
import { dataCache, _fullDataCache, applyDLCFilter } from '../core/data/cache.js';
import { loadData } from '../core/data/loader.js';
import { character, resetCharacter } from '../core/state/character-model.js';
import { buildDataIndexes } from '../core/data/indexes.js';

Object.defineProperty(window, 'dataCache',
    { get: () => dataCache, enumerable: true, configurable: true });
Object.defineProperty(window, 'character',
    { get: () => character, enumerable: true, configurable: true });

window.loadUpgradeData = loadData;
window.applyUpgradeDLCFilter = applyDLCFilter;
window.resetUpgradeCharacter = resetCharacter;
window.buildDataIndexes = buildDataIndexes;
</script>
```

### 3.5 副作用：`buildDataIndexes` bug 被修复

桥接脚本显式暴露 `window.buildDataIndexes`，且 `loadData()` 内部已包含索引构建，升级流程正常。

## 六、风险与回滚

| 风险 | 概率 | 缓解 |
|------|:--:|------|
| core/loader.js 的 fetch 失败率高于 $.getJSON | 低 | loader.js 已有 Promise.allSettled + 空数组回退 |
| `character` 属性缺失导致升级步骤报错 | 中 | 已补 `classExtraAll`，其他字段对齐验证过 |
| 桥接脚本加载时序（module 在 defer 之前） | 无 | ES Module 的 `<script>` 默认 defer，且在普通 defer 脚本之前执行 |

回滚方式：还原 upgrade.js 的 4 段删除，删掉 bridge 脚本，还原 upgrade.html。
