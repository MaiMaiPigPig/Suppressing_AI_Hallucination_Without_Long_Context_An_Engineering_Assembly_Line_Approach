# 需求-v0.4-002-J_handlers 引用路径调整

## 一、目标与背景

**人类出这个需求的目的**：handlers 层当前使用全局变量扩展模式（`handlers.xxx = handlers.xxx || {}`），依赖浏览器 `<script>` 标签的加载顺序。两个页面（character.html 和 upgrade.html）对 `handlers` 的声明方式还不一致。迁移到 ES Module 后需要统一 handlers 的加载和引用方式，但不移动 handlers 文件本身的位置。

**对应父文档任务**：任务 10

---

## 二、范围

### 包含
- `handlers` 声明方式统一（character.html 的 `character.js:36` 定义 vs upgrade.html 的内联 `<script>` 定义）
- 16 个 handlers/*.js 文件的加载方式调整（从 `<script>` 标签加载改为模块导入）
- `handlers/data-query.js` 的全局函数改为模块导出
- `handlers/index.js` 的 `processItemRules()` 保持参数传入方式，不依赖全局 `character`

### 不包含
- handlers 文件本身移动位置（仍在 `character/dnd_5r/handlers/`）
- handlers 的 parse 函数签名修改
- handlers 的解析策略修改
- 函数重命名 → v0.5

## 四、任务清单

### J1. 统一 handlers 声明方式

**当前问题**：
- `character.html`：通过 `creation/character.js` 中的 `var handlers = {};`（L36）定义
- `upgrade.html`：通过内联 `<script>var handlers = {};</script>`（L31）定义

**目标**：统一为模块导入方式，不再依赖全局 `handlers` 预声明。

**v0.4 边界**：
- ✅ 统一声明方式
- ❌ 不改 handlers 文件位置
- ❌ 不改 parse 函数签名

**验收标准**：
- [ ] `character.html` 和 `upgrade.html` 的 handlers 加载方式一致
- [ ] 不再出现 `var handlers = {}` 的全局声明

---

### J2. 调整 16 个 handlers/*.js 的加载方式

**当前模式**：
```javascript
// handlers/basic.js（当前）
handlers.basic = handlers.basic || {};
handlers.basic.parse = function(rule, character, options) { ... };
```

**目标模式**（二选一，由开发决定）：

**方案 A：注册表模式（推荐）**
```javascript
// handlers/basic.js（调整后）
export function parse(rule, character, options) { ... }

// handlers/index.js（注册表）
import * as basic from './basic.js';
export const handlerRegistry = {
  basic: basic,
  // ...
};
```

**方案 B：保持扩展模式但改为模块内注册**
```javascript
// handlers/basic.js（调整后）
import { handlers } from './index.js';
handlers.basic = handlers.basic || {};
handlers.basic.parse = function(rule, character, options) { ... };
```

**v0.4 边界**：
- ✅ 16 个文件均可通过 `import` 使用
- ❌ 不改 parse 函数的实现逻辑
- ❌ 不改解析策略

**验收标准**：
- [ ] 16 个 handlers/*.js 文件均可通过 `import` 使用
- [ ] 所有步骤的 handler 调用行为与迁移前一致

---

### J3. data-query.js 改为模块导出

**当前问题**：`handlers/data-query.js` 定义全局函数：
- `buildDataIndexes()`
- `findItemSourceTable()`
- `collectChainedRaceFeatures()`
- ...（其他全局查询函数）

这些函数通过全局作用域被 `character.js` 和 `upgrade.js` 调用。

**目标**：改为模块导出，由调用方 `import`。

**v0.4 边界**：
- ✅ 全局函数改为模块导出
- ❌ 不改函数实现
- ❌ 不改函数名

**验收标准**：
- [ ] `handlers/data-query.js` 的函数改为模块导出
- [ ] `creation/` 和 `upgrade/` 通过 `import` 引用这些函数
- [ ] 数据查询行为与迁移前一致
