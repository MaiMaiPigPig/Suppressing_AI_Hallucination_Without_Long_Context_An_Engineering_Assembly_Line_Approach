# 需求-v0.6-001_仓库拆分（上架工程与开发文档分离）

> ⚠️ **已废弃**：本文档已被「需求-V0.6-002_仓库拆分任务卡（双仓库落地）」替代。本文档中的仓库存放范围、仓库性质（远程 clone）、验收标准、工具链归属均以 002 为准。详见「缺陷单-V0.6-003_需求V0.6-001与002冲突.md」。

## 一、目标

将当前单一 Git 仓库拆分为两个独立仓库，使上架工程与开发过程文档彻底分离。

## 二、前置依赖

- [ ] v0.5 全部任务已完成并验收通过

## 三、范围

### 上架仓库

- TableChronicle/ 全部内容（Web 应用完整代码：Python 后端 + JS 前端 + 游戏数据 JSON）
- package.json、package-lock.json（ESLint / TypeScript 工具链）
- eslint.config.mjs（JS 代码规范，含项目全局变量声明）
- jsconfig.json（VS Code JS 项目配置，指向 TableChronicle 源码目录）
- .gitignore（裁剪版，仅保留运行代码相关忽略规则）

### 开发文档仓库

- 开发资源/ 全部内容（需求、设计、缺陷、任务卡、测试用例等开发过程资产）

### 不涉及

- node_modules/（已 gitignore，由 npm install 生成）
- .pytest_cache/（已 gitignore，由 pytest 生成）
- __pycache__/（已 gitignore，由 Python 生成）

## 四、处理方案

1. **上架仓库**：以 TableChronicle 内容为仓库根目录，工程配置文件（package.json 等）置于根目录
2. **开发文档仓库**：以开发资源内容为仓库根目录
3. **.gitignore**：按各自仓库的需求重新裁剪，互不含对方范围的忽略规则
4. TableChronicle/scripts/fix_subclass_id.py 为数据维护脚本，归入上架仓库

## 五、验收标准

- [ ] 上架仓库可独立 git clone 并正常运行
- [ ] 开发文档仓库可独立 git clone
- [ ] 两个仓库的 .gitignore 各自正确，不含对方文件的忽略规则
- [ ] 原仓库中的 node_modules、.pytest_cache、__pycache__ 不会进入任一新仓库
- [ ] 上架仓库中不含开发文档（需求、设计、缺陷等 .md 文件）
- [ ] 开发文档仓库中不含运行时代码（JS / HTML / CSS / Python / JSON 数据文件）
- [ ] 拆分后上架仓库 npm install 无报错

## 六、备注

- 拆分方式（git subtree / filter-repo / 手动重建）由开发评估决定，本需求不限定技术方案
- 上架仓库后续即为打包上线目标，与开发文档彻底解耦
