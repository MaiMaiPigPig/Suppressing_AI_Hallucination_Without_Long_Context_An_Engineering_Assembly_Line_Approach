## 缺陷 1：阶段2 验收编号与需求不一致，且文档内部自相矛盾

**严重程度**：🔴 阻塞

### 问题描述

需求 002 中卡 B 的验收标准编号为 **B1/B2/B3/B4**：

| 编号 | 内容 |
|------|------|
| B2 | csv→json 产出 |
| B3 | 回归测试执行 |
| B4 | ESLint 检查 |

但开发计划阶段2 使用了不同的编号：

| 阶段 | 开发计划写的编号 | 002 实际编号 |
|------|:-----------:|:---------:|
| 2.1 csv→json | **B4** | B2 |
| 2.2 回归测试 | **B5** | B3 |
| 2.3 ESLint | **B6** | B4 |

002 中不存在 B5 和 B6。

更严重的是，**同一份开发计划文档内部自相矛盾**：

| 位置 | csv→json | 回归测试 | ESLint |
|------|:------:|:------:|:------:|
| 阶段2（第97-112行） | B4 | B5 | B6 |

## 缺陷 2：卡C 缺少 C3 的显式验证步骤

**严重程度**：🟡 中等

### 问题描述

需求 002 卡C 验收标准 C3：

> 如卡C 执行后发现问题，旧仓库文件仍完整可用，可回退到原始状态重新来过

开发计划[阶段3](file:///f:/跑团工具/开发资源/ai文档集合/当前工程/开发计划-V0.6-003_仓库拆分（双仓库落地）.md#L115-L126) 的步骤为：

1. 确认仓库1 git log 有提交
2. 确认仓库2 git log 有提交
3. 删除旧 .git
4. 根目录 git status（确认非仓库）
5. 进入 TableChronicle\ git status
6. 声明"卡C检查点C1/C2/C3 ✅"

**问题**：步骤中没有任何操作验证"旧仓库文件仍完整可用"——没有检查 TableChronicle/ 的文件列表、没有检查开发资源/ 的文件列表、没有对比删除前后的文件状态。

虽然删除 .git 理论上不碰其他文件，但 C3 是需求明确要求的验收项，应该有对应的验证动作，而不是靠"理论上不会有事"跳过。

### 建议

在阶段3 增加一步：删除 .git 后列出 TableChronicle\ 和开发资源\ 的顶层目录/关键文件，人为确认与删除前一致。

### 处理结果

✅ 已修复。阶段3 第6步已新增 `dir` 命令检查目录结构 + 抽查关键文件。

## 缺陷 3：卡A 验收 A2 的验证步骤不够具体

**严重程度**：🟢 建议

### 问题描述

需求 002 的 A2：

> 程序独立运行正常：启动 `app.py`（Flask 5001）首页、车卡页、数据加载正常

开发计划阶段 1.1 第 7-8 步：

> 启动 `python app.py`，确认 Flask 5001 正常启动
> 浏览器访问首页、车卡页，确认数据加载正常

"数据加载正常"的判断标准是什么？是肉眼看一下页面不报错就行，还是检查浏览器控制台无报错、网络请求全部 200？需求 002 没有细写，但开发计划作为执行文档，应该给一个可执行的判断标准，否则不同人验证的结果不一致。

### 建议

补充判断标准，例如：浏览器控制台无报错、network 面板无 404/500、页面元素正常渲染。或直接写"见准绳②，由人工自行判断"。

### 处理结果

✅ 已修复。阶段1.1 第7步加了"控制台无 traceback"，第8步加了"浏览器控制台 F12 无红色报错、Network 面板无 404/500"。
