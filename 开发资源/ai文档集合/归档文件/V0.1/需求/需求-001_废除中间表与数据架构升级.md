# 需求单 需求-001: 废除中间表与数据架构升级

## 1. 目标与背景
- **要解决什么问题**：
  1. 现有 `link(id)` 中间表存在魔法数字不可读、AI 填写困难、与映射表职责重叠等问题
  2. 测试反馈现有 Schema 存在字段不匹配、枚举值缺失、数据类型不一致等问题
  3. 核心数据表（种族、职业、专长等）缺少 Schema 文档，开发无据可依
- **目标用户**：开发团队、AI 填数据工具、未来 DLC 扩展
- **核心价值**：数据引用人类可读、AI 可自举、程序可解析；为未来 DLC 即插即用和 AI 自动填数据打下基础

## 2. 范围
- **做什么（In Scope）**：
  1. 废除引用表，所有 `link(id)` 替换为自描述表达式
  2. 补充 10 份核心表 Schema 文档（种族、职业、专长、背景、技能、工具、武器、护甲、职业特性、种族特性）
  3. 每个 Schema 文档包含：表结构（字段名/类型/必填/说明）、枚举值列表（允许值及说明）、版本状态标记（✅已支持/⏳开发中/📋计划中）
  4. 开发 Python 迁移脚本，自动将现有 CSV 中的 `link(id)` 转换为自描述表达式
  5. 更新 `csv转json.py`，集成 `ExpressionParser` 类，支持解析全部 10 种自描述表达式类型
  6. 更新前端代码，用 `ExpressionParser` 替代 `link.js`，彻底移除 `link(id)` 相关兼容代码
  7. 已有 Schema 文档（法术、状态效果、战斗动作、怪物、场景与遭遇）补充枚举值列表和版本状态标记
  8. 所有 Schema 文档通过 `B_校验清单.md` 中的校验项
- **不做什么（Out of Scope）**：
  1. 不修改现有业务逻辑（车卡流程、战斗结算规则、AI DM 行为）
  2. 不新增游戏玩法功能
  3. 不修改已有稳定表的核心表结构，仅补充枚举值和状态标记
  4. 不处理 DLC 打包工具开发（已有 `07_DLC结构规范.md`）
  5. 不修改前端 UI/UX 设计

## 3. 功能需求（用户故事）
- **作为** 开发，**我想要** 自描述表达式替代 `link(id)`，**以便** 一眼看懂数据引用关系，不再查中间表
- **作为** AI 填数据工具，**我想要** 直接输出 `spells(class=3,lv=0)+2` 这类表达式，**以便** 不需要分配和维护中间表 ID
- **作为** 测试，**我想要** 每份 Schema 都有枚举值列表和版本状态，**以便** 知道哪些字段已可用、哪些还在开发
- **作为** 未来 DLC 开发者，**我想要** 数据架构支持即插即用，**以便** 新增数据不需要修改引擎代码

## 5. 风险与依赖
- **技术风险**：
  1. 引用表数据不完整，部分 `link(id)` 可能未定义，导致迁移脚本生成 `UNKNOWN_LINK(id)`
  2. 自描述表达式长度可能超出 CSV 单元格显示宽度
  3. JavaScript 正则与 Python 行为可能存在差异，导致前端解析失败
- **依赖项**：
  1. 现有 CSV 文件完整可读，无损坏或缺失
  2. 前端构建流程（Webpack/Vite 等）正常，能正确打包新 JS 文件
  3. 需要人类确认种族/职业等核心表的字段列表与现有 CSV 列名一致
