## 3. 攻击重点

### 3.1 重点一：表达式解析一致性（Critical）

**为什么先攻**：Python 和 JavaScript 正则行为可能存在差异，同一表达式在两端解析结果不同会导致数据错乱。

**攻击方式**：
1. 编写交叉验证脚本：用 Python 解析表达式，输出结构化结果，再用 JS 解析同样表达式，对比结果
2. 重点覆盖边界情况：
   - `spells(class=12,school=7,school=9)+2`（同一条件多值 OR）
   - `prerequisite(lv:class(11)=2)`（嵌套表达式）
   - `choose(skills(21,22))+1`（手动列表）
   - `[1]feats(type=44)+1,[2]spells(class=3,lv=0)+2`（多选一标记）

### 3.2 重点二：spell-level.js 改造验证（High）

**为什么先攻**：评审-002 发现此文件用 `extractLinkId()` 从 `rules` 字段提 link ID，迁移后需改为从自描述表达式解析参数。改动大，容易漏。

**攻击方式**：
1. 收集所有涉及法术等级的 code handler 测试用例
2. 验证 `spells(class=12,school=7)+2` 能正确提取 class=12, school=7
3. 验证 `spells(class=3,lv=0)+2` 能正确提取 class=3, lv=0（戏法）

### 3.3 重点三：车卡流程端到端（High）

**为什么先攻**：涉及 8 个前端文件，改动点多，任何一个出错都会导致车卡流程断裂。

**攻击方式**：
1. 逐步骤验证：
   - 选择有法术的种族（如人类），验证种族法术正确显示
   - 选择战士，验证职业特性（战斗风格、进阶职业等）正确渲染
   - 选择有选项选择的专长（如战斗风格），验证多选一格式正确
   - 选择有熟练项选择的背景（如工匠），验证 choose 表达式正确
   - 选择技能，验证技能熟练正确
2. 验证 `prerequisite(lv>=4)` 等前置条件在 UI 上的显示和校验

### 3.4 重点四：双向转换一致性（Medium）

**为什么先攻**：json转csv.py 是新增的，需要确保 JSON → CSV → JSON 往返后数据一致。

**攻击方式**：
1. 随机抽取 10 条 JSON 数据
2. 用 json转csv.py 转回 CSV
3. 再用 csv转json.py 转回 JSON
4. 对比原始 JSON 和往返后 JSON，验证无丢失

## 5. 风险评估

### 5.1 最可能崩溃的环节

| 风险 | 概率 | 影响 | 预防/应对 |
|---|---|---|---|
| Python/JS 正则行为差异 | 高 | 高 | 开发阶段做交叉验证，测试重点覆盖 |
| spell-level.js 改造出错 | 中 | 高 | 单独测试用例覆盖，边界情况验证 |
| 多选一格式 `[1]...[2]...` 渲染错误 | 中 | 中 | 车卡流程重点验证多选一场景 |
| 升级模块 upgrade.js 间接依赖 link | 中 | 中 | 确认 upgrade.js 的 proficiency_link 是否依赖引用表 |
| 往返转换数据丢失 | 低 | 中 | 自动化测试脚本验证双向一致性 |

### 5.2 回归风险

- `handlers/link.js` 删除后，如果有未知调用方会报错

**应对**：上线前全链路 grep，确保无遗漏。
