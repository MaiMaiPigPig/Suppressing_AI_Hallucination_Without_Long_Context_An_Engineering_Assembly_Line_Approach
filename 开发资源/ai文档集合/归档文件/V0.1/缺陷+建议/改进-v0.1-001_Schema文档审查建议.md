**示例**：

| 列名 | 英文名 | 类型 | 必填 | 状态 | 说明 |

## 二、枚举值完整性建议

### 2.1 怪物 AI 行为格式建议

**问题**：`08_怪物.md` 的 ai_behavior JSON 格式缺少完整的枚举值定义。

**建议补充**：

**action 枚举值**：
- attack_melee：近战攻击
- attack_ranged：远程攻击
- cast_spell：施法
- retreat：撤退
- dodge：闪避
- help：帮助
- flank：侧翼包抄
- special：特殊动作（见详情）

**condition 语法**：
- hp_above:X.X（生命值高于 X%）
- hp_below:X.X（生命值低于 X%）
- ally_injured：盟友受伤
- enemy_weak：敌人生命值低
- always：总是执行
- target_within:X：目标在 X 尺内

---

### 2.2 战斗动作效果数据格式建议

**问题**：`06_战斗动作.md` 的 effect_data 格式缺少 type 枚举值。

**建议补充**：

**type 枚举值**：
- damage：造成伤害
- heal：治疗
- apply_condition：施加状态
- remove_condition：移除状态
- buff：增益
- debuff：减益
- teleport：传送
- summon：召唤
- transform：变形

---

### 2.3 状态效果属性影响格式建议

**问题**：`05_状态效果.md` 的 stat_effects 的 type 值分散在示例中。

**建议**：在"属性影响格式"章节开头增加完整的 type 枚举表：

**type 枚举值**：

| type | 含义 | value 格式 |
|---|---|---|
| set | 设置为固定值 | 数值 |
| bonus | 加值（可为负） | 数值 |
| advantage | 优势 | true/false |
| disadvantage | 劣势 | true/false |
| half | 减半（向下取整） | 0.5 |
| immunity | 免疫某种伤害/状态 | 伤害类型字符串或状态 ID |
| resistance | 抗性 | 伤害类型字符串 |
| vulnerability | 易伤 | 伤害类型字符串 |

---

## 三、数据一致性建议

### 3.1 数据流文档与 Schema 统一

**问题**：数据流.txt 和 Schema 文档描述不一致，特别是对 `all` 这种特殊值的处理。

**建议**：
1. 将数据流.txt 中的所有字段说明迁移到对应的 Schema 文档中
2. 或将数据流.txt 标记为"废弃"，统一使用 Schema 文档作为数据定义来源
3. 在 Schema 中为 `all` 等特殊值增加明确的处理说明

---

### 3.2 职业表字段格式规范

**问题**：职业表的 `主属性建议` 字段格式不统一（有 `1` 有 `1|4`）。

**建议**：
1. 在 Schema 中明确定义 `主属性建议` 的格式：
   - 单属性：直接写 ID（如 `1`）
   - 多属性择一：用 `|` 分隔（如 `1|4`）
   - 多属性全要：用 `,` 分隔（如 `1,4`）
2. 在校验清单中增加对此字段格式的校验

---

## 四、引擎集成建议

### 4.1 DLC 依赖解析算法文档化

**问题**：多个 DLC 依赖同一本体时，加载顺序和覆盖规则未明确定义。

**建议**：在 `07_DLC结构规范.md` 中补充：

**加载顺序**：
1. 按 depends_on 拓扑排序
2. 同一层级的 DLC 按 id_prefix 升序
3. 相同 id 的数据，后加载的覆盖先加载的

**覆盖冲突检测**：
- 如果两个 DLC 覆盖同一本体数据，记录警告
- 如果两个 DLC 新增相同 id（未覆盖本体），报错拒绝加载

**示例**：
```
DLC-A depends_on [phb]
DLC-B depends_on [phb]
DLC-C depends_on [DLC-A, DLC-B]

加载顺序：phb → DLC-A → DLC-B → DLC-C
```
