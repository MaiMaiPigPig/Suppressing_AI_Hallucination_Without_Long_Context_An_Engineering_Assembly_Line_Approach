# 需求-V0.8-001_新增单元测试脚本

## 一、目标

为 `dnd_5r` 前端代码建立单元测试体系，覆盖核心工具函数和数据处理逻辑，减少人工回归测试成本。

## 二、前置依赖

- [ ] v0.6 全部任务已完成并验收通过

## 三、范围

### 3.1 包含

| 模块 | 说明 |
|------|------|
| `utils/` | 纯函数工具（HTML 转义、货币解析/转换/格式化） |
| `core/constants/` | 常量定义（属性 ID 列表、步骤数据字段映射） |

## 四、测试框架

**选型：Vitest**

- ESM 原生支持，与项目现有 ES Module 结构兼容
- 零配置，`npm install -D vitest` 即可使用
- 支持覆盖率报告生成

## 五、关键依赖处理

### 5.1 `dictionary.js` 的 `window` 全局依赖

**问题**：`translateDamageType()` 和 `translateProperties()` 通过 `window.DAMAGE_TYPE_MAP` / `window.PROPERTY_MAP` 读取映射表，测试环境无浏览器 `window`。

**方案**：将映射表从 `15-sheet-renderer.js` 中抽取为独立模块常量文件（如 `core/data/damage-type-map.js` 和 `core/data/property-map.js`），`dictionary.js` 改为 `import` 引入，消除对 `window` 的隐式依赖。

### 5.2 `core/data/` 缓存相关函数的测试策略

- `setDataCache()` / `setFullDataCache()` / `resetCache()`：直接传入 mock 数据对象验证读写
- `applyDLCFilter()`：构造含 `dlc` 字段的 mock 数据，验证过滤结果
- `replacePlaceholdersInText()`：纯文本处理，直接传入字符串和 item 对象验证替换结果
- `loadData()` 本身（含 `fetch`）不测，端到端流程留到 UI 回归测试

### 5.3 `handlers/` 层测试策略

测试目标：验证"规则字符串 → 结构化对象"的翻译是否正确。

- 对每个 handler 的 `parse()` 函数，输入各种规则字符串，验证返回对象的字段值
- 对 `choose.js` 的 `splitArgs()`，验证嵌套括号的正确拆分
- 对 `index.js` 的 `parseRule()`，验证路由分发是否正确（各类规则走到对应 handler）

| `utils/currency.js` | `formatCurrency()` | 格式化输出（零值显示 `0GP`、进位正确、只显示非零单位） |
| `core/constants/character-constants.js` | `ABILITY_NAMES` | 数组内容正确性（6 个属性 ID） |
| `core/constants/character-constants.js` | `STEP_DATA_FIELDS` | 17 步车卡字段映射完整性 |

| `core/data/dictionary.js` | `translateProperties()` | 单属性/多属性/带数字前缀（如 `1,2` → `轻型、投掷`）、空值处理 |
| `core/data/cache.js` | `setDataCache()` / `setFullDataCache()` / `resetCache()` | 读写正确性、reset 后为空 |
| `core/data/cache.js` | `applyDLCFilter()` | 白名单表过滤、非白名单表全量复制、无 `dlc` 字段的项始终保留、空列表默认 `['phb']` |

| `handlers/choose.js` | `splitArgs()` | 嵌套括号内逗号不拆分、空字符串、单层无嵌套 |

| `handlers/choose.js` | `parse()` | 完整规则解析、总数提取、标题生成、括号不匹配/缺少总数等错误处理 |
| `handlers/filter.js` | `parse()` | `spell(...)` 各类参数（class/lv/school/dice/id）、`tool(...)` / `weapon(...)` / 直接指定 `id` / 复合筛选 / 未匹配返回 `success:false` |
| `handlers/index.js` | `parseRule()` | 各类型规则路由正确（basic/choose/filter/attribute/level/operation/...）、复数形式前缀归一化（`spells(`→`spell(`）、未识别规则返回 `unknown` |
