## 一句话

`monsters(id=15)` 的 chain 引用没坏在**解析**上（正则已能正确拆分），而是坏在**数据源加载**上——`dataCache` 里根本没有 `monsters` 这张表，查不到目标。

---

## 缺陷描述

### 数据路径断裂

[class_features.json L5968](file:///f:/跑团工具/TableChronicle/data/json/class_features.json#L5968) — id=333 牧境·原初行侣：
```json
"chain": "monsters(id=15)"
```

当 `processChainReferences` 处理此 chain 时，经过 [review.js L371-L379](file:///f:/跑团工具/TableChronicle/character/dnd_5r/creation/steps/review.js#L371-L379)（缺陷-v0.3-009 修复后的代码）：

```javascript
const targetTable = dataCache[tableName];  // dataCache["monsters"] → undefined
if (targetTable && Array.isArray(targetTable)) {  // false → 跳过
    // 永远不会进入
}
```

### 对照：`tools(id=24)` 是通的

`dataCache` 加载了 `tools` 表（见 `upgrade.js L118` / `character.js L213`），所以 `tools(id=24)` 能走通。而 `monsters` 在加载清单中不存在。

### 两条流程的 monsters 数据源

| 流程 | 文件 | 是否加载 monsters |
|:---:|------|:---:|
| 车卡 | `creation/character.js` 第 205-219 行加载清单 | ❌ 无 |
| 升级 | `upgrade/upgrade.js` 第 109-135 行加载清单 | ❌ 无 |
| — | lookup_table.json | 仅有引用标记 `"source_table": "monsters"`，无实际数据 |

### 影响范围

- **id=333 原初行侣（德鲁伊·牧境 Lv3）**：chain 是 `monsters(id=15)`，引用的是死数据。升级流程中 `collectSelectionsFromSource` 无法通过此 chain 获取额外数据
- 该特性另有 `"extra": "class_extra_all"` 标记，class_extra 的数据获取走的是另一条路（`dataCache.extraByFeatureId` / `class_extra.json`），所以可能**功能上影响不大**——但 chain 确实处于断裂状态

---

## 建议

需要确定两个问题：

1. **monsters 数据从哪来？** `lookup_table.json` 里标记了 `source_table: "monsters"`，但实际数据文件不存在。需要决定：
   - 创建 `monsters.json` 并载入 dataCache
   - 或将 monsters 数据合并到现有表中
   - 或确认此 chain 本就不需要工作，清除这条死引用

2. **是否需要修复？** 当前原初行侣特性通过 `extra: "class_extra_all"` 和 `rules: "monsters(id=13)"` 已有部分功能可用，chain 的 `monsters(id=15)` 可能只是旧数据规范的残留。需要开发确认这条 chain 的真实用途。
