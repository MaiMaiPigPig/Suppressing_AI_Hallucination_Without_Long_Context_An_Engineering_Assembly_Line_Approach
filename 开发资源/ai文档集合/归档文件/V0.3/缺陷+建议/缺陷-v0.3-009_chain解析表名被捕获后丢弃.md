## 一句话

开发在 review.js 的 `processChainReferences` 里加了正则 `(\w+)\(id=(\d+)→(\d+)\)` 来解析 `proficiency(id=443→460)`，正则捕获组 `[1]` = 表名、`[2]` = 起始ID、`[3]` = 结束ID。但表名 `[1]` 到手后**从未使用**，后面的 `findInAllTables(targetId)` 是**全表盲搜**——既然不想用表名，为什么还把表名写进格式里？

---

## 证据

### 证据 1：正则匹配 vs 实际消费

[review.js L371-L378](file:///f:/跑团工具/TableChronicle/character/dnd_5r/creation/steps/review.js#L371-L378)：

```javascript
const rangeMatch = chainStr.match(/(\w+)\(id=(\d+)→(\d+)\)/);
// 输入: "proficiency(id=443→460)"
// rangeMatch[1] = "proficiency"  ← 表名，后面完全没用到
// rangeMatch[2] = "443"           ← 起始ID
// rangeMatch[3] = "460"           ← 结束ID

if (rangeMatch) {
    const startId = parseInt(rangeMatch[2], 10);
    const endId = parseInt(rangeMatch[3], 10);
    // ↑ 只用了 [2] 和 [3]，[1] 凭空消失
    for (let id = startId; id <= endId; id++) {
        chainIds.push(id);
    }
}
```

### 证据 2：findInAllTables 是全表遍历

[review.js L386](file:///f:/跑团工具/TableChronicle/character/dnd_5r/creation/steps/review.js#L386)：

```javascript
const target = findInAllTables(targetId);
```

这个函数在所有已注册的表中搜索 ID，不限定表名。如果将来另一条 chain 写成 `class_extra(id=5→10)` 且 ID 5~10 在 proficiency 表里也存在，会捡到错误的条目。

### 证据 3：表名有用但不用的悖论

数据已经改了——[class_features.json L4690](file:///f:/跑团工具/TableChronicle/data/json/class_features.json#L4690)：

```json
"chain": "proficiency(id=443→460)"
```

格式里明确写了 `proficiency`。如果表名毫无意义，为什么数据要写它？直接写成 `"id(443→460)"` 就够了。既然写了，代码就应该消费它。

## 输入输出追踪

```
输入: chain = "proficiency(id=443→460)"
  ↓
正则: /(\w+)\(id=(\d+)→(\d+)\)/.exec(chain)
  ↓
[1]="proficiency" [2]="443" [3]="460"
  ↓
代码: parseInt([2]) = 443, parseInt([3]) = 460
  ↓                          ↑ [1] 完全未引用
展开为 [443, 444, ..., 460]
  ↓
for (const targetId of chainIds)
  ↓
findInAllTables(targetId) ← 盲搜全部表，不管表名
  ↓
碰巧 proficiency.id=443~460 在这个代码库中唯一，不会找错
但如果将来有别的表用了同一段 ID，就错了
```

---

## 影响范围

| 影响 | 详情 |
|------|------|
| **当前运行时** | 低 — 奥法骑士 443~460 / 诡术师 461~498 的 ID 在当前数据中唯一 |
| **正确做法** | 用 rangeMatch[1] 定位目标表，在该表内按 ID 搜索，而非全表盲搜 |
| **潜在风险** | 将来添加其他表的范围 chain 时，两表 ID 重叠会返回错误条目 |
| **性能** | 每次 `findInAllTables` 遍历多个表，比指定表名搜索慢，但当前数据量小不构成实际影响 |

---

## 建议

用表名约束搜索：

```javascript
if (rangeMatch) {
    const tableName = rangeMatch[1];  // "proficiency"
    const startId = parseInt(rangeMatch[2], 10);
    const endId = parseInt(rangeMatch[3], 10);
    for (let id = startId; id <= endId; id++) {
        const target = findInTable(tableName, id);  // 只查指定表
        if (target) {
            chainTargets.push(target);
        }
    }
}
```

或者如果确实不想用表名（所有 ID 全局唯一），至少把数据格式里的表名去掉，别给人"这里写了表名"的错觉。
