## 缺陷描述

任务卡 v0.3-001 已明确要求将 `class_features.json` 中两处 chain 值从旧的错误格式修正为正确格式。但截至测试执行时，数据**完全没有改动**。

### 预期

```json
// 奥法骑士 (id=261)
"chain": "proficiency(id=443→460)"

// 诡术师 (id=362)
"chain": "proficiency(id=461→498)"
```

```json
// 奥法骑士 (id=261)
"chain": "growup（283→302）"    ← 全角括号 + 错误ID

// 诡术师 (id=362)
"chain": "growup（303→322）"    ← 全角括号 + 错误ID
```

## 错误对照

| | 当前值（错误） | 应为 |
|---|---|---|
| 奥法骑士 chain | `growup（283→302）` | `proficiency(id=443→460)` |
| 奥法骑士括号 | 全角 `（）` | ASCII `()` |
| 奥法骑士 ID | 283→302（武僧/圣武士的数据） | 443→460 |
| 诡术师 chain | `growup（303→322）` | `proficiency(id=461→498)` |
| 诡术师括号 | 全角 `（）` | ASCII `()` |
| 诡术师 ID | 303→322（错误范围） | 461→498 |

---

## 影响范围

1. **奥法骑士和诡术师的施法功能完全依赖错误数据** — chain 指向的 283-322 是武僧和圣武士的 proficiency 数据，不是法术位数据
2. **即使 range 解析能工作**，取到的也是完全错误的条目
3. **全角括号**导致 `growup(` 前缀不被正则匹配，依赖可选组的回退机制侥幸工作

---

## 建议

直接修改 `class_features.json` 中 id=261 和 id=362 的 `chain` 字段为正确值：

- id=261: `"chain": "proficiency(id=443→460)"`
- id=362: `"chain": "proficiency(id=461→498)"`

## 审查意见（2026-09-27）

### ⚠️ 与缺陷-v0.3-008 是同一问题的一体两面，应合并处理

本缺陷要求将 chain 数据修正为 `proficiency(id=443→460)`，但 [缺陷-v0.3-008](file:///f:/跑团工具/开发资源/ai文档集合/当前工程/缺陷-v0.3-008_chain格式与消费代码不兼容.md) 已证明：即使改成这个格式，`processChainReferences` 用 `parseInt` 解析仍会得到 `NaN`，chain 照样不会被消费。

**只改数据不改解析逻辑，改了也白改。** 数据格式和解析逻辑是同一个问题的两面，拆成两张单子分开处理会导致：修了 v0.3-004 后数据格式正确但功能仍未生效，然后又得回头看 v0.3-008。

**建议**：将 v0.3-004 和 v0.3-008 合并为一张缺陷单，标题改为"chain 字段数据格式与解析逻辑不匹配——需同步修正"。
