## 缺陷描述

`handlers/table-ref.js` 被两个 HTML 页面加载了，但 `index.js` 的 `parseRule` 函数不包含 table-ref 的路由，导致生产代码中该处理器**完全不可达**。同时 `feature-selection.js` 中对 `type === 'table-ref'` 的判断分支也永远不会触发。

---

## 证据

### 证据 1：HTML 加载了 table-ref.js

[character.html L318](file:///f:/跑团工具/TableChronicle/character/dnd_5r/creation/character.html#L318)：
```html
<script src="../handlers/table-ref.js"></script>
```

[upgrade.html L32](file:///f:/跑团工具/TableChronicle/character/dnd_5r/upgrade/upgrade.html#L32)：
```html
<script src="../handlers/table-ref.js"></script>
```

HTML 侧的加载是正常的，`handlers.tableRef` 在全局作用域可用。

### 证据 2：index.js 未路由 table-ref

[index.js](file:///f:/跑团工具/TableChronicle/character/dnd_5r/handlers/index.js) 的 `parseRule` 函数覆盖了 15 种处理器类型（basic、attribute、level、operation、proficiency、chain、selection、resource、special、table-map、feat-require、weapon-mastery、filter、choose、dice），但**没有 table-ref**。

```bash
# 搜索 "table-ref" 或 "tableRef" 在 index.js 中 — 无结果
grep -n "table-ref\|tableRef" TableChronicle/character/dnd_5r/handlers/index.js
# 无匹配
```

### 证据 3：feature-selection.js 的死代码分支

[feature-selection.js L117](file:///f:/跑团工具/TableChronicle/character/dnd_5r/creation/steps/feature-selection.js#L117)：
```javascript
} else if (result.type === 'table-ref') {
    // 固定引用：直接添加，不需要用户选择
    pendingSelections.push({
        // ...
    });
}
```

此分支被 `parseRule` 的返回结果触发，但 `parseRule` 永远不会返回 `type: 'table-ref'`，所以此分支是死代码。

### 证据 4：唯一调用方是测试工具

[test.js](file:///f:/跑团工具/TableChronicle/backstage/test/test.js)（后台手动测试工具）直接调用 `handlers.tableRef.parse()`，不经过 `parseRule` 路由。这只能通过后台手动操作触发，生产流程中不可达。

### 证据 5：实际数据中无 table-ref 格式的 rules

```bash
# 搜索 rules 字段中 "spell=数字" / "skill=数字" 等 table-ref 格式
grep -rn '"rules": "[a-z]+=\d' TableChronicle/data/json/
# 无匹配
```

所有 data JSON 的 `rules` 字段中不存在 `spell=56` 这种格式。`package_details.json` 的 `source` 字段中有 `weapon=2` 格式，但 `source` 字段不被 `processItemRules` 扫描，走的是 `package.js` 自定义处理。

## 建议

二选一：

**方案 A（如果 table-ref 格式将来需要用）**：在 `index.js` 的 `parseRule` 中补充路由：

```javascript
// 在 parseRule 函数中，step 5 (proficiency) 之后插入
// Step 5b: table-ref（固定引用：item=X, spell=X, weapon=X 等）
if (rRoute.match(/^(item|spell|weapon|skill|tool|armor|language)=\d+$/)) {
    return handlers.tableRef ? handlers.tableRef.parse(rule) : null;
}
```

同时在 `feature-selection.js` L117 的分支中确保消费逻辑完整。

**方案 B（如果不需要）**：从 HTML 中移除 `<script src="../handlers/table-ref.js">` 引用，删除 `feature-selection.js` 中的死代码分支，归档 `table-ref.js`。
