## 缺陷-008: proficiency_link 解析 + 查表逻辑在代码库中重复 6 次，level-select.js 内部重复 2 次

| 字段 | 内容 |

### 缺陷描述

`proficiency_link` 字段的解析 + 查 proficiency 表取值，这一整套逻辑在代码库中出现了 **6 次**。`review.js` 中已有共享函数 `getCountFromProficiencyRef()`，但其余 5 处全部是内联手写，没有调用它。

尤其 `level-select.js` ——**同一个文件内部就出现了两次完全相同的模式**（武器精通 L420-444、职业额外 L592-615），连局部共用函数都没提。

这次 v0.3-002 的 `linkIds` → `refIds` 重命名摸过了每一处，但并未趁机收敛，代码仍然散落。

### 证据

#### 6 处重复位置一览

| # | 文件 | 行号 | 上下文 | 是否调用共享函数 |
|---|---|---|---|---|
| 1 | `creation/steps/review.js` | L569-L617 | `getCountFromProficiencyRef()` | ✅ 本身就是共享函数 |
| 2 | `creation/steps/feature-selection.js` | L256-L291 | 武器精通处理 | ❌ 内联手写 |
| 3 | `creation/steps/sheet.js` | L863-L897 | `getFeatureProficiencyValues()` | ❌ 内联手写（但封装了函数） |
| 4 | `upgrade/steps/level-select.js` | L420-L444 | weaponMasteryResults 处理 | ❌ 内联手写 |
| 5 | `upgrade/steps/level-select.js` | L592-L615 | classExtraItems 处理 | ❌ 内联手写 |
| 6 | `upgrade/upgrade.js` | L978-L1000 | 武器精通处理 | ❌ 内联手写 |
| 7 | `upgrade/upgrade.js` | L1159-L1184 | classExtraItems 处理 | ❌ 内联手写 |

> 注：sheet.js 的 `getFeatureProficiencyValues()` 虽然封装了函数，但函数体内部仍手写了一份完整的 parse 逻辑，与 `getCountFromProficiencyRef` 不同。

#### level-select.js 内部两份代码对比（关键证据）

**L420-444（武器精通处理）**：

```javascript
var proficiencyCount = 0;
if (feature.proficiency_link && dataCache.proficiency) {
    var refIds = [];
    if (Array.isArray(feature.proficiency_link)) {
        refIds = feature.proficiency_link;
    } else if (typeof feature.proficiency_link === 'string' && feature.proficiency_link.trim() !== '') {
        try {
            var parsed = JSON.parse(feature.proficiency_link);
            if (Array.isArray(parsed)) refIds = parsed;
        } catch(e) {
            refIds = feature.proficiency_link.split(',').map(function(s) { return parseInt(s.trim(), 10); }).filter(function(n) { return !isNaN(n); });
        }
    }
    for (var li = 0; li < refIds.length; li++) {
        var refEntry = dataCache.proficiency.find(function(e) { return e.id === refIds[li]; });
        if (refEntry && refEntry.type === 'weapon_mastery') {
            var entries = dataCache.proficiency.filter(function(e) {
                return e.type === 'weapon_mastery' &&
                       String(e.class_id) === String(classId) &&
                       e.level <= level;
            });
            if (entries.length > 0) {
                var best = entries.reduce(function(max, e) { return e.level > max.level ? e : max; }, entries[0]);
                proficiencyCount = parseInt(best.value) || 0;
            }
        }
    }
}
```

**L592-615（职业额外处理）**：

```javascript
var count = 0;
if (sourceFeature.proficiency_link && dataCache.proficiency) {
    var refIds = [];
    if (Array.isArray(sourceFeature.proficiency_link)) {
        refIds = sourceFeature.proficiency_link;
    } else if (typeof sourceFeature.proficiency_link === 'string') {
        try { refIds = JSON.parse(sourceFeature.proficiency_link); }
        catch(e) { refIds = sourceFeature.proficiency_link.split(',').map(function(s) { return parseInt(s.trim(), 10); }); }
    }
    refIds.forEach(function(refId) {
        var entry = dataCache.proficiency.find(function(e) { return e.id === refId; });
        if (entry) {
            var matches = dataCache.proficiency.filter(function(e) {
                return e.type === entry.type &&
                       String(e.class_id) === String(cls.id) &&
                       e.level <= level;
            });
            if (matches.length > 0) {
                var best = matches.reduce(function(max, e) { return e.level > max.level ? e : max; }, matches[0]);
                count = parseInt(best.value) || 0;
            }

```

两个代码块的核心逻辑高度相似（解析 `proficiency_link` → 取 refIds → 查 proficiency 表 → 取 count），完全可以提取为一个文件内局部函数或调用已有的 `getCountFromProficiencyRef`。

#### 各实现间的行为差异（次要问题）

| 实现 | 取第几个 refId | 类型筛选方式 |
|------|:---:|---|
| `review.js` getCountFromProficiencyRef | **第 1 个**（break 跳出） | `refEntry.type`（动态） |
| `feature-selection.js` | **第 1 个**（break 跳出） | `refEntry.type === 'weapon_mastery'`（硬编码） |
| `level-select.js` L420 | **第 1 个**（for 循环，break 在每个迭代中隐含，但 overwrite） | `refEntry.type === 'weapon_mastery'`（硬编码） |
| `level-select.js` L592 | **最后 1 个**（forEach 遍历全部，最后覆盖） | `entry.type`（动态） |
| `upgrade.js` L978 | **第 1 个 weapon_mastery**（不 break，但逐次覆盖） | `refEntry.type === 'weapon_mastery'`（硬编码） |
| `upgrade.js` L1159 | **最后 1 个**（forEach 遍历全部） | `entry.type`（动态） |

当 `proficiency_link` 包含多个不同 type 的 refId 时，各实现的行为不一致。

### 建议

1. `level-select.js` 内部两份逻辑应提取为局部共用函数（或直接复用 `getCountFromProficiencyRef`，若跨模块加载可行）
2. `upgrade.js` 同理
3. `feature-selection.js` 也应统一调用共享函数而不是内联手写
4. 统一后，取 refId 策略应保持一致（建议取第一个匹配的 或 取最后一个，统一即可）
