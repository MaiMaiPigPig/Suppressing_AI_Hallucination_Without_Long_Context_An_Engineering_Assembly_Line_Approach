## 缺陷-001: chain 引用的目标表与 ID 范围双重错误（任务卡核心假设错误）

| 字段 | 内容 |
|---|---|
| 严重程度 | **Critical** |
| 优先级 | P0 |
| 来源 | 任务卡-v0.3-001 |
| 状态 | ⏳ 待确认 |

### 缺陷描述

任务卡 v0.3-001 声称：
- id=283~302 是"奥法骑士的施法条目"，属于 `class_features` 表
- id=303~322 是"诡术师的施法条目"，属于 `class_features` 表
- 新格式应为 `class_features(id=283→302)` / `class_features(id=303→322)`

**这是双重错误**——目标和表都错了。

### 证据

**错误一：目标表是 `proficiency`（环位熟练），不是 `class_features`**

`growup` 前缀在 [table-map.js](file:///f:/跑团工具/TableChronicle/character/dnd_5r/handlers/table-map.js) 中映射到 `proficiency.json`。`class_features.json` id=261 和 id=362 的 chain 字段都是 `growup(…)`，所以数据源是 **proficiency 表（环位熟练）**，不是 class_features。

这一点任务卡自身也矛盾——3.1 节数据现状中写的是 `growup` 前缀，却在"应该改为"建议中写 `class_features(…)`，表名就对不上。

**错误二：ID 范围完全错误**

正确的数据在 [环位熟练.csv](file:///f:/跑团工具/开发资源/data/csv导出/环位熟练.csv) 中：

|------|--------|-------------|--------|------|
| 奥法骑士 | 19 | **443 → 460** | 18 条 | 5(战士) |
| 诡术师 | 2 | **461 → 498** | 38 条 | 9(游荡者) |

**环位熟练.csv 实际数据（奥法骑士，[L444-L461](file:///f:/跑团工具/开发资源/data/csv导出/环位熟练.csv#L444-L461)）**：
```

19,445,2,,spell_preparation,8,,,,,,,,,,5,法术准备,
```

**环位熟练.csv 实际数据（诡术师，[L462](file:///f:/跑团工具/开发资源/data/csv导出/环位熟练.csv#L462) 起）**：

### 错误对照表

| | 任务卡声称 | 实际正确值 |
|---|---|---|
| 奥法骑士 数据表 | `class_features` | **`proficiency`（环位熟练）** |

1. **当前 chain 数据 `growup（283→302）` 和 `growup（303→322）` 本身就是错误的**——指向了错误的 ID 范围，无论解析与否都取不到正确数据

## 缺陷-002: 前端范围解析正则与数据括号不匹配

| 字段 | 内容 |
|---|---|
| 严重程度 | **Medium** (当前侥幸工作) |
| 优先级 | P1 |
| 来源 | 任务卡-v0.3-001 |
| 状态 | ⏳ 待确认 |

### 缺陷描述

- **预期结果**：正则表达式应与数据格式匹配
- **实际结果**：`selection.js` 的正则使用 ASCII 半角括号 `()`，但 `class_features.json` 实际数据使用全角中文括号 `（）`（U+FF08 / U+FF09）

### 证据

**数据**（[class_features.json:L4690](file:///f:/跑团工具/TableChronicle/data/json/class_features.json#L4690)）：
```json
"chain": "growup（283→302）"     ← 全角括号 U+FF08 / U+FF09
"chain": "growup（303→322）"     ← 全角括号 U+FF08 / U+FF09
```

**正则**（[selection.js:L139](file:///f:/跑团工具/TableChronicle/character/dnd_5r/handlers/selection.js#L139)）：
```javascript
var rangeMatch = rule.match(/(?:growup\s*\(\s*)?(\d+)\s*→\s*(\d+)(?:\s*\))?/);
//                                    ASCII (         ASCII )              ASCII )
```

### 为什么当前侥幸工作

正则的 `(?:growup\s*\(\s*)?` 部分尝试匹配 `growup(`，但数据中是 `growup（`（全角括号），这步失败。由于该组是**可选的**（`?`），正则引擎跳过 `growup（`，直接在字符串中间匹配到 `283→302`。所以结果仍然返回 `startId=283, endId=302`。

### 风险

- 当前靠可选组的回退机制勉强工作，逻辑脆弱
- 如果将来字符串中出现其他数字+箭头组合，会误匹配
- **任务卡要求的 `class_features(id=283→302)` 新格式使用 ASCII 括号——正则能匹配新格式，但前提是全角括号旧格式被替换**

### 建议

本次实装时应一并规范化：正则统一支持 ASCII 括号 `()`，数据中的全角 `（）` 必须替换。

### 当前情况（2026-09-27）

✅ 任务卡 v0.3-001 已明确要求"统一使用 ASCII 半角括号 `()`，替换全角中文括号 `（）`"（见范围 3.1 节、约束第 5 条）。

当前实际数据仍为全角括号：`class_features.json` L4690 和 L6490 两处 `chain` 值仍为 `growup（283→302）` / `growup（303→322）`（全角括号）。这些将在 v0.3-001 实装阶段随数据层修改一并替换为 ASCII 括号。

## 缺陷-004: Python 测试与 JS 实现在箭头符号上不一致

| 字段 | 内容 |
|---|---|
| 严重程度 | **Medium** |
| 优先级 | P1 |
| 来源 | 任务卡-v0.3-001 |
| 状态 | ⏳ 待确认 |

### 缺陷描述

- **预期结果**：Python 测试与 JS 实现覆盖相同的语法格式
- **实际结果**：Python 测试用 `->`（ASCII 双字符），JS 代码和实际数据用 `→`（Unicode U+2192 单字符）

### 证据

**Python 测试**（[test_expression_parser.py:L71](file:///f:/跑团工具/开发资源/data/tests/test_expression_parser.py#L71)）：
```python
r = ExpressionParser.parse('growup(303->322)')   # ASCII "->" 双字符
```

**Python ExpressionParser**（[csv转json.py:L622](file:///f:/跑团工具/开发资源/data/csv转json.py#L622)）：
```python
m = re.match(r'^(\w+)\s*\(\s*(\d+)\s*(?:→|->|\.\.|-)\s*(\d+)\s*\)\s*$', expr)
#                                           ↑ Unicode  ↑ ASCII
# Python 端同时支持两种，但测试只覆盖了 ASCII
```

**JS 实现**（[selection.js:L139](file:///f:/跑团工具/TableChronicle/character/dnd_5r/handlers/selection.js#L139)）：
```javascript
var rangeMatch = rule.match(/(?:growup\s*\(\s*)?(\d+)\s*→\s*(\d+)(?:\s*\))?/);
//                                                      ↑ 仅 Unicode
// JS 端只支持 Unicode →
```

**实际数据**（[class_features.json:L4690](file:///f:/跑团工具/TableChronicle/data/json/class_features.json#L4690)）：
```json
"chain": "growup（283→302）"     ← Unicode →
```

### 影响范围

- Python 测试覆盖了 `->` 但遗漏了实际使用的 `→`
- 如果将来 Python 侧也需要处理 `class_features(id=283→302)`，测试用例需要补充 `→` 的测试

### 当前情况（2026-09-27）

✅ 任务卡 v0.3-001 已修正：
- 约束第 6 条明确要求"箭头统一使用 Unicode `→`（U+2192），同时兼容 ASCII `->`"
- 新增验收标准 001-9：解析器同时支持 `→` 和 `->`
