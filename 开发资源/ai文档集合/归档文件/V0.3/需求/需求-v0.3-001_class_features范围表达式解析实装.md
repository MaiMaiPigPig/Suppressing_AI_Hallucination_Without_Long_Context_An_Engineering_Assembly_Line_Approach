# 需求-v0.3-001：proficiency 范围表达式解析实装

> **版本规划**：v0.3 实装。当前版本已完成中间表废除迁移，此需求纳入 v0.3。
> **审查修正**：缺陷-v0.3-001（7 个子缺陷已全部确认并修正）

---

## 1. 目标

实装 `proficiency(id=起始→结束)` 范围表达式的前端解析与数据获取逻辑，使战士(5)奥法骑士、游荡者(9)诡术师的"施法"特性在车卡时正常生效。

---

## 2. 背景 / 用户故事

### 2.1 历史沿革（v0.1 数据迁移遗留问题）

本项目在 v0.1 完成了"中间表废除"重构，核心改动是将 CSV 中所有 `link(id)` 格式的数据引用迁移为"自描述表达式"。详见归档文件：[开发资源\ai文档集合\归档文件\V0.1\需求\需求-001_数据迁移映射清单.md](file:///f:/跑团工具/开发资源/ai文档集合/归档文件/V0.1/需求/需求-001_数据迁移映射清单.md)

### 2.2 本需求的由来

v0.1 迁移时，有两处数据使用了特殊语法 `growup（283→302）`：

| 位置 | 字段 | 说明 |
|------|------|------|
| class_features.json id=261 | chain | 战士(5)奥法骑士 — "施法"特性 |
| class_features.json id=362 | chain | 游荡者(9)诡术师 — "施法"特性 |

**经审查确认**：
- `growup` 在 `table-map.js` 中映射到 `proficiency.json`（环位熟练表），而非 `class_features` 表
- `class_features.json` 中的 `chain` 字段值 `growup（283→302）` 指向的 ID 范围 283~302 在 `proficiency.json` 中**不存在**
- `proficiency.json` 中奥法骑士的实际数据是 id=443~460，诡术师是 id=461~498
- 数据来源：[环位熟练.csv](file:///f:/跑团工具/开发资源/data/csv导出/环位熟练.csv) L444-L499

**因此当前数据无论怎么解析都取不到正确数据**，需要同时修正数据和解析逻辑。

### 2.3 当前数据现状

| 位置 | 当前值（错误） | 期望新值（正确） |
|------|--------------|----------------|
| class_features.json id=261 | `growup（283→302）` | `proficiency(id=443→460)` |
| class_features.json id=362 | `growup（303→322）` | `proficiency(id=461→498)` |

**前端现状**：
- `handlers/selection.js` 已能解析 `growup(303→322)` 和 `303→322` 的范围语法
- 但 **未支持带表名的语法**（如 `proficiency(id=443→460)`）
- 范围解析结果只返回 `startId`/`endId`，**未指定目标表名**
- **全局搜索确认**：没有任何 JS 代码消费 `subtype === 'range'` 的解析结果

## 3. 范围（做）

1. 修改 `class_features.json` 中两处 `chain` 字段，使用正确表名和 ID 范围
2. 前端解析器支持带表名的范围语法 `proficiency(id=443→460)`
3. 解析结果需包含目标表名字段，供数据获取层使用
4. 新增消费逻辑：根据解析结果从对应表中获取 id 范围内的数据
5. 确保车卡时奥法骑士、诡术师的"施法"特性正确显示环位熟练数据

---

## 4. 范围（不做）

1. 不实现其他表的范围表达式（如 `spells(id=1→10)`）— 除非有明确需求
2. 不修改 `csv转json.py` — 数据层不需要动
3. 不修改 `table-map.js` 中的 `growup` 映射 — 本次直接在新语法中指定表名

---

## 5. 约束

1. 语法格式：`表名(id=起始→结束)`，仅支持连续整数范围
2. 表名必须使用规范定义的英文名（如 `proficiency`）
3. 范围边界包含（闭区间）：`443→460` 表示 443, 444, ..., 460
4. 逆序范围返回空列表，不崩溃
5. 括号统一使用 ASCII 半角 `()`
6. 箭头统一使用 Unicode `→`（U+2192），同时兼容 ASCII `->`
