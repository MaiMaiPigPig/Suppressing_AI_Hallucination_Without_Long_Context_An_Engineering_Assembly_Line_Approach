## A. 子职法术面板验证

> **覆盖维度**：功能、数据、回归
> **核心风险**：回归测试从未覆盖奥法骑士和诡术师子职路径，法术面板的戏法/准备/环位数据未经验证。

### TC-A-001 — 奥法骑士_Lv3_法术位

| 项目 | 内容 |
|------|------|
| 前置条件 | 创建战士角色 → 通过升级系统升到 Lv3 → 选择奥法骑士子职 |
| 执行步骤 | 1. 从 welcome 页进入车卡流程<br>2. 选人类 + 战士 + 任意背景<br>3. 完成创建 → 步到升级系统<br>4. 导入新角色 → 升到 Lv3 → 选奥法骑士<br>5. 检查升级预览/角色卡上的法术面板 |
| 验证点 | 1. 法术面板不为空、不报错<br>2. 环位数量和等级正确（对照 proficiency.json class_id=5, level=3 的 slot_1~slot_9）<br>3. 显示"已知戏法数 ≥ 2"<br>4. 显示"已准备法术数 = 3"（Lv3 战士: spell_ability=INT, 3个1环） |
| 预期结果 | 法术面板给出 2 戏法 + 3 准备法术 + 2个1环法术位。无 NaN、undefined、空白 |
| 关联缺陷 | 缺陷-004（数据未修正）、缺陷-008（chain 死数据） |

### TC-A-002 — 奥法骑士_Lv4_法术位递增

| 项目 | 内容 |
|------|------|
| 前置条件 | 继承 TC-A-001 的角色，继续升到 Lv4 |
| 执行步骤 | 1. 在当前角色上继续升级到 Lv4<br>2. 检查法术面板 |
| 验证点 | 1. 戏法数 ≠ Lv3 的值（递增）<br>2. 准备法术数递增（Lv4: 4 准备）<br>3. 环位数递增（Lv4: 3个1环） |
| 预期结果 | 数值全部递增，无回退 |
| 关联缺陷 | 缺陷-004 |

### TC-A-003 — 诡术师_Lv3_法术位

## C. 数据正确性（纯静态，不依赖浏览器）

> **覆盖维度**：数据
> **核心风险**：proficiency.json ID 不连续、chain 指向不存在的条目、新格式引用断裂。

### TC-C-001 — proficiency.json ID 连续性

| 项目 | 内容 |
|------|------|
| 执行方式 | 读取 `proficiency.json`，遍历全部行验证 id 字段连续自增 |
| 验证点 | 1. id 从 (first) 到 (last) 无跳号<br>2. 无重复 id |
| 脚本形式 | 纯 Python/JS 脚本，读取 JSON 遍历即可 |

### TC-C-002 — class_features.json chain 格式校验

| 项目 | 内容 |
|------|------|
| 执行方式 | 读取 `class_features.json`，筛选 chain 字段非空的条目，校验格式 |
| 验证点 | 1. chain 要么是逗号分隔的数字串（如 `"4,5,6"`），要么是合法表达式（如 `proficiency(id=443→460)`）<br>2. 不会出现 `growup（283→302）` 这种中文括号和范围混用的格式<br>3. 奥法骑士(261) 和 诡术师(362) 的 chain 指向的 proficiency.json 条目全部存在 |
| 关联缺陷 | 缺陷-004（数据未修正）、缺陷-008（格式不兼容） |

### TC-C-003 — proficiency 条目归属一致

| 项目 | 内容 |
|------|------|
| 执行方式 | 对奥法骑士(261) chain 指向的 proficiency 条目（443-460），验证 class_id=5（战士） |
| 验证点 | 443-460 的 class_id 全部为 5，type 分布在 cantrip/preparation/spell_slots |
| 注意 | 这是防御性校验——防止 proficiency 数据归属到错误的职业 ID |
