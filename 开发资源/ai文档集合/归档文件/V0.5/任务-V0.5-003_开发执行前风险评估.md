# 任务-v0.5-003_开发执行前风险评估

## 一、目标

在正式执行 v0.5-001（命名规范落地）和 v0.5-002（合并重复选择收集逻辑）之前，由开发对代码现状进行风险评估，输出风险清单和应对方案，避免执行过程中出现意外阻塞。

## 二、前置依赖

- [ ] v0.5-001 需求已阅读完毕
- [ ] v0.5-002 需求已阅读完毕
- [ ] 开发已熟悉当前 `core/`、`creation/` 目录结构

## 三、评估范围

### 必须评估
- `core/` 下所有文件的函数依赖关系
- `creation/steps/` 下所有步骤文件的函数调用链
- `creation/ui/` 下 UI 组件的引用关系
- `utils/` 下工具函数的引用方

### 可选评估（如时间允许）
- `upgrade/` 模块（本次不处理，但需确认是否被 `creation/` 意外引用）
- `handlers/` 层接口边界（对照 v0.5-001 要求自查）

## 四、评估内容

### 4.1 全局替换风险

| 检查项 | 方法 | 风险说明 |
|--------|------|----------|
| `calcMod` → `calculateModifier` | grep 全量搜索 | 可能误伤含 `calcMod` 子串的其他标识符（如 `recalcMod`） |
| `getCfgs` → `getConfigurations` | grep 全量搜索 | 确认无其他文件导出同名函数 |
| `res` → `result` | grep 全量搜索 | 极易误伤：`response`、`restore`、`preserved` 等含 `res` 子串的标识符 |
| `tmp`/`temp` → 按用途命名 | 逐文件审查 | 同一文件中多处 `tmp` 可能含义不同，需分别判断 |
| `el`（非 DOM）→ 按用途命名 | 逐文件审查 | 需区分 DOM 场景（保留 `el`）与非 DOM 场景 |

**要求**：每个替换项输出「风险等级 + 具体误伤案例 + 规避措施」。

### 4.2 文件重命名风险

| 检查项 | 方法 | 风险说明 |
|--------|------|----------|
| 步骤文件加编号（`race.js` → `01-race.js`） | 检查所有 import/动态 import 路径 | `lifecycle.js` 中 `STEP_RENDERERS` 使用动态 import，路径硬编码需同步更新 |
| `sheet.js` 拆分为 `sheet-main.js` + `sheet-renderer.js`（v0.4 已完成） | 确认 v0.5 不再涉及 | 如 v0.5 需再次调整，需确认引用方已全部更新 |

**要求**：列出所有引用被重命名文件的位置，确认无一遗漏。

### 4.3 函数提取风险

| 检查项 | 方法 | 风险说明 |
|--------|------|----------|
| `translateDamageType()` 提取到 `core/data/dictionary.js` | diff 两处实现 | 需确认 `export.js` 和 `sheet-renderer.js` 的实现**完全一致**，无微小差异 |
| `translateProperties()` 提取到 `core/data/dictionary.js` | diff 两处实现 | 同上 |
| `getClassFeatures()` 改名 | grep 所有调用方 | `class.js` 和 `review.js` 的调用方需同步更新 |
| `escapeHtml()` 确认已统一 | grep `creation/` 下是否仍有独立定义 | `creation/` 已通过 `utils/html.js` 统一入口，本次无需提取；仅需确认无残留副本 |

**要求**：提取前必须 diff 两处实现，如有差异需记录并上报产品决策。

### 4.4 handlers 接口自查

| 检查项 | 方法 | 风险说明 |
|--------|------|----------|
| 每个 handler 模块的公开入口函数 | grep `window.handlers.xxx` 或 `import { xxx }` | 误改入口函数名将导致步骤文件调用失败 |
| 内部辅助函数是否被外部调用 | grep 函数名全量搜索 | 某些"内部"函数可能被其他 handler 或步骤文件间接调用 |

**要求**：输出每个 handler 模块的「不可改名函数清单」，代码审查时核对。

### 4.5 v0.5-002 合并逻辑风险

| 检查项 | 方法 | 风险说明 |
|--------|------|----------|
| `collectPendingSelections()` 调用方 | grep 全量搜索 | 确认所有调用方已改为 `addPendingSelectionsFromItem()` 或等效逻辑 |
| `processItemRules()` 输出格式 | 对比两处输出 | `collectPendingSelections()` 手动解析的输出格式与 `processItemRules()` 可能不一致 |
| 选择弹窗状态更新 | 黑盒测试 | 合并后选择弹窗是否正常弹出、选择后是否正确保存 |

**要求**：合并前必须确认输出格式一致，如有差异需上报产品决策。
