## 二、测试策略

### 为什么是这些维度

纯结构重构，最大风险是**改坏了**而非**没做新功能**。攻击策略：

| 优先级 | 维度           | 为什么                                                 |
| ------ | -------------- | ------------------------------------------------------ |
| P0     | **回归** | 重构的核心验收标准：迁移前后行为一致                   |
| P0     | **数据** | DLC 过滤、缓存一致性、步骤清理——数据错一步，后续全错 |
| P1     | **功能** | 新增的模块接口是否按设计工作                           |
| P1     | **边界** | 步骤切换的边界条件（第一步/最后一步/步骤跳过）         |
| P2     | **异常** | 数据加载失败、模块导入失败                             |
| P2     | **体验** | 步骤切换流畅度、loading 态                             |
| P3     | **性能** | 动态 import 首次加载延迟                               |

### 分层测试方法

- **黑盒**：浏览器中完整跑一次车卡流程 + 一次升级流程，观察全量行为
- **白盒**：对照设计文档核对文件存在、目录结构、模块导出
- **数据对比**：迁移前后同一操作的 character 对象 JSON 对比

## 六、风险提示

1. **Esbuild 打包无 tree-shaking**：当前构建工具是 esbuild，不支持 tree-shaking。模块化后未使用的模块不会自动排除，bundle 体积可能增大。测试时需对比迁移前后的 HTML 加载时间。
2. **浏览器缓存**：动态 import 产生独立 chunk 文件，用户在迁移版本发布后可能遇到旧缓存导致加载失败。测试建议包含无缓存模式（DevTools 禁用缓存）验证。
3. **全局变量残留引用**：除代码中显式的 `character.xxx =` 外，HTML 内也可能通过 `<script>` 标签赋值全局变量。HTML 审查（R3/R4）是回归重点。
