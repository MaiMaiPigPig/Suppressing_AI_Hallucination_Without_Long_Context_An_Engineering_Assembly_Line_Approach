# 产品功能描述 — 车卡系统 v0.2

> **版本**：v0.2  
> **状态**：已完成  
> **适用范围**：DND 5R 角色创建流程（不含升级系统）  
> **目标读者**：测试团队

---

## 一、产品定位

车卡工具是面向 DND 5R 玩家的在线角色创建器。用户按步骤选择种族、职业、背景等，最终生成完整角色卡，支持导出 JSON 存档和 PDF。

**核心设计**：所有数据驱动的选择项（原本散落在各步骤的映射表/引用表选择）全部集中到**步骤14（特性总览）**统一处理。

---

## 二、车卡流程（16个可见步骤）

进度条显示 1-8、10-17（步骤9未实装，编号已跳过）。

| 步骤 | 名称 | 功能描述 |
|:----:|------|----------|
| 0 | 欢迎页 | 新建角色 / 从 JSON 导入角色 / 从升级页返回时自动加载角色数据 |
| 1 | 种族选择 | 展示可选种族列表（受 DLC 过滤影响），点击种族查看详情面板（速度、体型、特性按等级分组），选择种族 |
| 2 | 亚种选择 | 展示当前种族的可用亚种，选择亚种；无亚种时自动跳过 |
| 3 | 职业选择 | 展示可选职业列表（名称、生命骰、主属性），点击职业查看详情面板（武器/护甲/豁免/技能熟练），选择职业 |
| 4 | 职业套装 | 根据职业的 `item_choice` 字段展示可选起始装备套装，选择套装；套装内含初始金币 |
| 5 | 背景选择 | 展示可选背景列表（含技能预览），点击背景查看详情面板（属性/技能/专长/工具），选择背景 |
| 6 | 背景套装 | 根据背景的 `suit_id` 字段展示可选起始套装，选择套装；套装内含初始金币 |
| 7 | 属性分配 | 两种模式：①随机（4d6丢1，生成多组可选，选一组后分配到六维）；②购点（27点分配到六维，8-15分档计费）。支持"推荐分配"按钮 |
| 8 | 背景加值 | 按背景的 `attr` 字段指定的属性列表分配 +2/+1（共3点）。可解绑为任意六维属性加值，单项上限20 |
| 10 | 技能选择 | 职业技能（从职业 `skill_prof` 列表选 `count` 项）+ 背景技能（从背景 `skills` 列表选）。可分别解绑为从全部技能任选 |
| 11 | 专长确认 | 默认显示背景推荐的专长（`bg.feat`），可解绑为从所有起源专长（`feats.type=42`）任选，选择后查看专长详情（含前置条件） |
| 12 | 法术选择 | 根据职业施法配置（`spellcasting.json`）显示：戏法数、已知法术数/准备法术数/法术书数量、各环位法术位。支持按学派/等级过滤，选择法术 |
| 13 | 商城购物 | 左侧显示已有物品（来自套装，只读），右侧分类浏览商品（冒险用品/武器/护甲/工具/魔法物品），加入购物车。金币 = 职业金币 + 背景金币 - 购物车总价，不允许超支 |
| 14 | 特性总览 | **集中处理所有来源的待选特性**。扫描种族/亚种/职业/子职/背景/背景套装/已选专长的全部特性，递归处理连锁引用，生成待选队列。有则展示选择界面，无则显示"所有特性已处理完毕" |
| 15 | 角色详情 | 填写名字（必填）、玩家、等级（固定1，不可改）、阵营（9宫格下拉）。选择语言（3种，特性已获得的语言自动标记不可选）。填写个人特点/理想/羁绊/缺点/背景故事 |
| 16 | 角色卡 | 完整角色卡预览：六维属性及调整值、豁免加值、技能加值、已选法术、武器/装备、所有特性汇总 |
| 17 | 保存导出 | 导出 JSON（完整角色数据，可重新导入）/ 导出 PDF（角色卡）/ 跳转升级系统 |

## 三、核心机制

### 3.1 特性总览（步骤14）

**设计目的**：将原本散落在各数据字段中的 `link(id)` 引用选择，全部后移到一个步骤集中处理。

**扫描来源**（按顺序）：
1. 基础种族（`character.race`）
2. 亚种（`character.subrace`）
3. 职业（`character.class`）
4. 子职（`character.subclass`）
5. 背景（`character.background`）
6. 背景套装（`character.bgPackage`）
7. 已选专长（`character.selectedFeat`）

**扫描逻辑**（对每个来源递归执行）：
1. 解析来源的 `rules` / `tool` 字段（通过 handlers 系统）
2. 处理 `chain` 字段的连锁引用（在所有数据表中搜索 ID，递归处理目标）
3. 处理 `choice` / `rules` / `code_effects` 同表链引用
4. 如果是职业：收集 1~当前等级 的所有职业特性，递归处理每个特性
5. 如果是子职：收集 1~当前等级 的所有子职特性，递归处理每个特性
6. 收集 `class_extra` 额外选项（如战士战技、术士魔能祈唤），按"效果名字"分组，去 `proficiency.json` 查当前等级给几个可选项

**处理结果**：
- 需要用户选择的项目 → 加入 `character.pendingSelections` 队列，在步骤14展示选择界面
- 直接引用（`table-ref`）→ 自动添加到角色数据（如自动加入法术列表并标记为 `lockedSpells`）
- 数值规则（`basic`，如 `hp_per_lv+2`）→ 自动累加到角色数据

**选择项类型**（9大类）：

| 类型 | 说明 |
|------|------|
| 技能 | 从候选技能中选 N 项 |
| 工具 | 从候选工具中选 N 项 |
| 武器 | 从候选武器中选 N 项（含武器精通） |
| 法术 | 从候选法术中选 N 项 |
| 语言 | 从候选语言中选 N 项 |
| 护甲 | 从候选护甲中选 N 项 |
| 专长 | 从候选专长中选 N 项 |
| 专精 | 从候选技能中选 N 项（expertise） |
| class_extra | 职业额外选项（战技、魔能祈唤等） |

**返回修改**：用户从步骤15返回步骤14时，已保存的选择状态（`featureSelections`）会恢复到选择界面，允许修改。

### 3.2 解绑机制

4个解绑开关，**全部是为适配不同 DM 的房规**：

| 开关 | 所在步骤 | 默认限制 | 解绑后 |
|------|----------|----------|--------|
| classSkill | 步骤10 | 只能从职业技能列表选 `count` 项 | 可从全部技能任选，数量限制放开 |
| bgSkill | 步骤10 | 只能从背景技能列表选 | 可从全部技能任选 |
| bonus | 步骤8 | 只能给背景指定属性加值 | 可给任意六维属性加值 |
| feat | 步骤11 | 只能选背景推荐专长 | 可从所有起源专长任选 |

解绑仅放开前端可选范围，不强制校验数量。数量限制由 DM 现场把控。

### 3.3 步骤回退清理

用户点击"上一步"返回前面步骤并修改选择时，**后续步骤的数据自动清空**。

| 回退到步骤 | 被清空的数据 |
|-----------|-------------|
| 1 | race, subrace, lockedSpells |
| 2 | subrace |
| 3 | class, subclass |
| 4 | classPackage |
| 5 | background |
| 6 | bgPackage |
| 7 | abilities |
| 8 | backgroundBonus |
| 10 | classSkills, backgroundSkills, allSkills |
| 11 | selectedFeat |
| 12 | selectedSpells, lockedSpells |
| 13 | currency, shoppingItems |
| 14 | 无（总览步骤本身不存数据，但会重新扫描） |
| 15 | name, player, alignment, personalTraits, ideals, bonds, flaws, backstory, selectedLanguages |

### 3.4 法术系统

**施法配置来源**：`spellcasting.json`

| 配置项 | 说明 |
|--------|------|
| spellcasting_ability | 施法属性（智力/感知/魅力） |
| preparation_method | 准备方式：1=known（已知）, 2=prepared（准备）, 3=spellbook（法术书） |
| spellbook_start | 法术书初始数量 |
| spellbook_gain_per_level | 每级增加法术书数量 |

**法术数据**：`proficiency.json`（type=spell 相关条目）

**lockedSpells**：由种族/职业特性自动给予的法术（`table-ref` 自动添加），用户在法术选择页**不能取消**。

### 3.5 商城购物

**金币计算**：
- 职业金币 = 职业套装 `desc` 中解析出的金币（PP×1000 + GP×100 + SP×10 + CP）
- 背景金币 = 背景套装 `desc` 中解析出的金币
- 购物车总价 = Σ（物品价格 × 数量）
- 剩余金币 = 职业金币 + 背景金币 - 购物车总价

**限制**：剩余金币**不能为负**，超支时禁止购买。

**已有物品**：来自套装的物品只读展示，不可出售或替换。

### 3.6 导出 JSON

导出内容包含**车卡后的完整角色数据**，用于存档和重新导入。

**核心字段**：
- 基础选择：raceId, subraceId, classId, subclassId, backgroundId
- 属性：abilities, backgroundBonus
- 技能：classSkills, backgroundSkills, allSkills
- 专长：selectedFeat
- 法术：selectedSpells, lockedSpells
- 选择结果：featureSelections（tools / weapons / spells / languages / armors / feats / skills / expertise / classExtra）
- 购物：shoppingItems, currency
- 详情：name, player, alignment, level, personalTraits, ideals, bonds, flaws, backstory, selectedLanguages
- 元数据：version, createdAt

## 五、Handler 规则解析系统

车卡流程依赖 JavaScript Handler 系统解析数据中的自描述表达式。

**主入口**：`handlers/index.js`

**关键 Handler**：

| Handler | 功能 |
|---------|------|
| basic.js | 基础数值规则（如 `hp_per_lv+2`） |
| choose.js | 手动选择（如 `choose(skills(21,22))+1`） |
| filter.js | 条件筛选（如 `spells(class=3,lv=0)+2`） |
| proficiency.js | 熟练项规则 |
| chain.js | 连锁引用（如 `chain:54`） |
| selection.js | 选择项管理 |
| feat-require.js | 专长前置条件校验 |
| weapon-mastery.js | 武器精通 |
| table-ref.js | 表引用（直接引用某表某 ID） |
| table-map.js | 表映射 |
| data-query.js | 数据查询工具函数 |

## 六、已知问题

### CHARA-001：步骤14数据来源查询不完整
- **问题**：`json_verify` 在步骤14只查询了 `class_features.json`，缺少 `spells.json` 和 `weapons.json`
- **影响**：步骤14中来自法术和武器的选择项可能验证失败
- **示例**：酸液飞溅（`spells.json#4`）、匕首（`weapons.json#19`）、巨棒（`weapons.json#34`）

## 七、与 v0.1 的差异（本版本重点）

本版本（v0.2）的核心改动是**废除中间表与数据架构升级**：

1. **自描述表达式**：所有 `link(id)` 语法已替换为新表达式语法（`feats(id=5)`、`spells(class=3,lv=0)+2` 等）
2. **特性总览集中化**：原本分散在各步骤的选择项，全部集中到步骤14统一处理
3. **Handler 系统**：新增/改造了前端规则解析引擎，支持10种表达式类型
4. **数据层改造**：CSV → JSON 转换工具已集成 ExpressionParser

## 八、数据架构与流转说明

### 8.1 数据层级概览

车卡系统的数据分为三层：

```
原始数据层（CSV） → 结构化数据层（JSON） → 运行时数据层（角色对象）
```

- **原始数据层**：`开发资源/data/csv导出/` 目录下的 CSV 文件，由人工维护
- **结构化数据层**：`TableChronicle/data/json/` 目录下的 JSON 文件，由 `csv转json.py` 从 CSV 生成
- **运行时数据层**：前端 `character` 对象，用户操作过程中动态变化

### 8.2 核心数据表详解

#### 8.2.1 种族系统

**表：种族.csv**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 唯一标识符 |
| 名字 | string | 种族名称（中文） |
| 从属 | int | **关键字段**：`0`=主种族，其他值=亚种（指向主种族的ID） |
| 等级 | int | 特性等级（固定为1） |
| 物种 | string | 物种类型ID（对应字典表） |
| 体型 | string | 体型ID列表（如"2,7"表示中型和小型） |
| 速度 | int | 移动速度（尺） |
| 特性chain: | string | 种族特性ID列表（逗号分隔），引用 `种族特性.csv` 的 id |
| dlc | string | DLC标识（如"phb"=玩家手册） |
| 详情 | string | 详细描述文本 |

**数据示例**：
```
id=1, 名字=阿斯莫, 从属=0  ← 主种族
id=11, 名字=白龙, 从属=2  ← 龙裔(id=2)的亚种
id=21, 名字=卓尔, 从属=4  ← 精灵(id=4)的亚种
```

**查询逻辑**：
- 步骤1展示种族列表：`SELECT * FROM 种族 WHERE 从属=0 AND dlc IN (enabledDLCs)`
- 步骤2展示亚种列表：`SELECT * FROM 种族 WHERE 从属={选中的种族ID}`

---

**表：种族特性.csv**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 唯一标识符 |
| 名字 | string | 特性名称 |
| 英文名 | string | 英文名称 |
| 骰娘互动 | string | 骰娘系统交互数据（如"d4*n"表示掷n个d4） |
| 选择 | string | **需要用户选择的项目ID列表**（逗号分隔）。有值则在步骤14弹出选择界面 |
| 车卡数据 | string | **自描述表达式**，定义自动获得的效果（如"spells(id=11)"自动习得光亮术） |
| 其他代码效果 | string | 其他代码层面的效果 |
| 详情 | string | 详细描述文本 |

**关键字段解析**：
- **选择字段**：如果有值（如"7,11"），表示该特性包含需要用户手动选择的子项。步骤14会解析这些ID并生成选择界面
- **车卡数据字段**：自描述表达式，由 Handler 系统解析：
  - `spells(id=11)` → 自动习得法术#11（光亮术）
  - `spells(class=12, lv=0)+1` → 从法师戏法中选1个
  - 直接引用（无choose/filter）→ 自动添加到角色数据，标记为 lockedSpells

**数据流向**：
```
种族.特性chain: → 解析为ID列表 → 查询种族特性表 → 
  ├─ 有"选择"字段 → 加入待选队列（步骤14让用户选）
  └─ 有"车卡数据"字段 → Handler解析 → 
       ├─ 含choose/filter → 加入待选队列
       └─ 纯table-ref → 自动应用（如自动加法术）
```

#### 8.2.2 职业系统

**表：职业.csv**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 唯一标识符 |
| 名字 | string | 职业名称 |
| 职业 | string | 英文标识（如"barbarian"、"wizard"） |
| 主职特性 | string | **各等级的职业特性ID列表**（逗号分隔），引用 `职业特性.csv` |
| 专长等级 | string | 可选专长的等级（如"4,8,12,16,19"表示这些等级可选ASl） |
| 子职等级 | string | 选择子职的等级（如"3,6,10,14"表示这些等级必须选子职） |
| 是否施法者 | int | 0=非施法者，1/2/3=施法者（对应spellcasting.preparation_method） |
| 喜好 | string | 职业偏好标签 |
| 主属性建议 | string | 推荐的主属性ID（可多个，用"|"分隔，如"1|4"表示力量或敏捷） |
| 推荐属性 | string | 推荐的六维属性值（如"15 13 14 10 12 8"） |
| 生命骰 | string | 生命骰类型（如"D12"、"D8"） |
| 升级生命值 | int | 每级增加的生命值（取平均或掷骰） |
| 豁免熟练 | string | 熟练豁免的属性ID列表（如"2,10"=敏捷+体质豁免） |
| 工具熟练 | string | **自描述表达式**，定义工具熟练项（如"tools(type=67)+3"=选3种乐器） |
| 技能熟练项 | string | 可选技能ID列表（逗号分隔） |
| 数量 | int | 可选技能数量 |
| 武器熟练 | string | 武器熟练ID列表（如"63,64"=简易+军用武器） |
| 甲类型 | string | 护甲熟练ID列表（如"2,3,5"=轻甲+中甲+盾牌） |
| 物品选择(根据商品id选择) | string | 可选套装ID列表（引用 `套装.csv`） |
| 详情 | string | 详细描述 |
| dlc | string | DLC标识 |
| 英文名 | string | 英文名称 |

**数据流向**：
```
职业.主职特性 → 解析为各等级特性ID列表 → 查询职业特性表 → 
  ├─ 1级特性 → 车卡时立即应用（如野蛮人狂暴、战士战斗风格）
  ├─ 高级特性 → 升级时应用（本版本不涉及）
  └─ 特性中的"车卡数据"/"特性chain:" → 递归处理

职业.技能熟练项 + 职业.数量 → 步骤10的职业技能候选列表
职业.工具熟练 → Handler解析 → 可能产生待选项（步骤14）
职业.物品选择 → 步骤4的套装候选列表
```

---

### 8.4 自描述表达式语法速查

在上述数据表中，多个字段使用自描述表达式（替代旧版 `link(id)` 语法）：

| 表达式类型 | 语法示例 | 说明 |
|-----------|---------|------|
| ID引用 | `feats(id=5)` | 引用专长表#5 |
| 条件筛选 | `spells(class=3, lv=0)+2` | 从牧师戏法中选2个 |
| 手动选择 | `choose(skills(21,22))+1` | 从指定技能中选1个 |
| 工具选择 | `tools(type=66)+3` | 从工匠工具中选3个 |
| 武器选择 | `weapons(id=63), weapons(type=0)+1` | 简易武器+1个近战武器 |
| 属性提升 | `ability(25)+1` | 魅力+1 |
| HP提升 | `hp_per_lv+2` | 每级HP+2 |
| 速度提升 | `speed+10` | 速度+10 |
| 法术位 | `spell_slot(lv=1)+1` | 1环法术位+1 |
| 熟练度 | `Proficiency>pure+2` | 2项技能专精 |
| 前置条件 | `prerequisite(lv>=4)` | 等级>=4 |
| 复合前置 | `prerequisite(lv>=4),prerequisite(ability(25)>=13)` | 多个前置条件AND |

### 10.2 "选择"字段与"车卡数据"字段的区别

这两个字段在种族特性.csv中职责不同：

| 字段 | 触发条件 | 处理方式 | 示例 |
|------|----------|----------|------|
| 选择 | 字段有值 | 查询同表ID获取子特性，展示给用户选择 | 光辉掌者.选择="7,11" → 用户选天堂飞翼或死灵环绕 |
| 车卡数据 | 字段有值 | Handler解析自描述表达式 | 光辉掌者.车卡数据="" (无)，法师戏法.车卡数据="spells(class=12,lv=0)+1" → 从法师戏法选1个 |

**简单理解**：
- **选择** = "这个特性有几个子选项，让用户选一个"
- **车卡数据** = "这个特性有自描述表达式效果，需要Handler解析"

两者可以同时存在，也可以只有一个生效。

### 10.3 chain 字段的跨表搜索

`chain` 字段的值是逗号分隔的ID列表，这些ID**可能来自任意表**。搜索函数 `findInAllTables(targetId)` 按以下顺序搜索：

1. `race_features.json`（种族特性）
2. `class_features.json`（职业特性）
3. `feats.json`（专长）
4. `spells.json`（法术）
5. `weapons.json`（武器）
6. `armors.json`（护甲）
7. `tools.json`（工具）
8. `items.json`（物品）
9. `languages.json`（语言）
10. `skills.json`（技能）

找到第一个匹配的就返回，不再继续搜索。**因此不同表的ID不能重复**（当前数据设计已保证这一点）。
