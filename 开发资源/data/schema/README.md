# TableChronicle 数据表 Schema 文档

## 本文档是写给谁看的

- **AI 助手**：从规则文本自动提取数据、生成 CSV
- **人类开发者**：理解数据结构设计、人工校验 AI 输出
- **DLC 作者**：创作新的内容包（种族、职业、法术、怪物等）

## 核心设计理念

### 1. DLC 即插即用
每个 DLC 是一个独立数据包，有自己的目录和文档，但遵循统一的 Schema 规范。
游戏引擎读取时，按依赖顺序合并所有 DLC 的数据。

```
DLC-0 (phb/玩家手册) ──→ DLC-1 (怪物图鉴) ──→ DLC-2 (自定义模组)
        ↑                        ↑                      ↑
   基础种族职业法术          新增怪物              覆盖/扩展任意表
```

### 2. 数据分层
| 层级 | 说明 | 示例 |
|---|---|---|
| 原始数据 | 规则书中的描述文本 | "你向施法距离内一点创造酸液泡..." |
| 结构化数据 | 提取成 CSV 的字段 | 目标类型=sphere, 目标尺寸=5 |
| 运行时数据 | JSON + 程序解析后的对象 | {area: {shape: "sphere", radius: 5}} |
| AI 理解数据 | 给 AI DM 的语义描述 | "对5尺范围内所有生物造成强酸伤害" |

### 3. 向后兼容
现有车卡数据（`csv导出/` 目录）不动。新架构是增量封装：
- 旧数据继续用旧的 `csv转json.py` 转换
- 新 DLC 数据用新的 Schema 规范 + 新的转换脚本
- 最终合并成统一的 JSON 供前端使用

### 4. 自描述表达式（v1.0 新增）
废除引用表（中间表），所有数据引用使用自描述表达式：
- `feats(id=5)` 代替 `link(1)`
- `spells(class=3,lv=0)+2` 代替复杂的引用表筛选
- 人类可读，AI 可自举，程序可解析

详见 `10_自描述表达式规范.md`

## AI 快速开始

如果你是 AI，被要求"从规则文本提取数据"，请按以下步骤：

1. **读 `00_通用约定.md`** → 理解 id 分配、引用语法、必填规则
2. **读 `10_自描述表达式规范.md`** → 理解新的自描述表达式语法（替代旧的 link(id)）
3. **读对应表的 Schema** → 理解该表有哪些列、每列填什么
4. **读 `99_附录/A_填写示例.md`** → 看一个完整的从文本到 CSV 的例子
5. **提取数据** → 输出 CSV 格式
6. **自检** → 对照 `99_附录/B_校验清单.md` 检查

## 人类快速开始

如果你是人类开发者：

1. **读 `00_通用约定.md`** → 理解整体设计思路
2. **读 `10_自描述表达式规范.md`** → 理解新的表达式语法和迁移计划
3. **挑你关心的表读 Schema** → 比如你在做战斗模块，重点看 `04_法术.md` + `05_状态效果.md`
4. **参考现有数据** → 对照 `csv导出/` 里的真实数据理解字段用法

## 关键术语

| 术语 | 含义 |
|---|---|
| DLC | 可下载内容包，一个独立的数据集合 |
| Schema | 数据表的结构定义（有哪些列、什么类型、什么规则） |
| 本体 | DLC-0，即基础规则数据（对应现在的 phb） |
| 覆盖 | DLC 可以修改本体的某行数据（用相同 id） |
| 新增 | DLC 可以添加本体没有的数据（用新 id） |
| 引用 | 一个表的数据指向另一个表的 id |
| Chain | 连锁引用，A 特性触发 B 特性 |
| 自描述表达式 | 新的引用语法，如 `spells(class=3,lv=0)+2` |
