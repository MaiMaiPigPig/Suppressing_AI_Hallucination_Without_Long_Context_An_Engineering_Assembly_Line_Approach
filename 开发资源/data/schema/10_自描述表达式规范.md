# 10_自描述表达式规范（替代引用表）

## 一、设计目标

1. **废除引用表**：消除 `link(id)` 魔法数字，所有引用自描述
2. **人类可读**：一看就懂，不需要查表
3. **AI 可自举**：AI 从规则文本直接输出表达式，不需要分配 ID
4. **程序可解析**：统一语法，一套解析器处理所有表达式
5. **向后兼容**：过渡期内支持旧 `link(id)` 语法

---

## 二、表达式语法总览

### 2.1 基本引用

```
格式：表名(条件)+数量

示例：
feats(id=5)              → 专长表 id=5 的条目
feats(name=魔法学徒)      → 专长表名字=魔法学徒的条目
spells(id=56)            → 法术表 id=56 的条目（至圣斩）
weapons(type=63)         → 武器表 type=63 的所有条目（简易武器）
skills(type=3)           → 技能表 type=3 的所有条目（技能类）
tools(type=66)           → 工具表 type=66 的所有条目（工匠工具）
```

### 2.2 多条件筛选

```
格式：表名(条件1,条件2,条件3)+数量

示例：
spells(class=3,lv=0)+2       → 牧师(class=3)的戏法(lv=0)中选2个
spells(class=12,school=11)+2 → 法师(class=12)塑能学派(school=11)法术选2个
spells(lv=1,school=9,10)+1   → 1环预言/惑控法术选1个
weapons(category=63,64)+1    → 简易或军用武器选1个
```

**条件连接规则**：
- 同一条件多次出现 = OR（如 `school=9,10` = 学派是9或10）
- 不同条件 = AND（如 `class=3,lv=0` = 职业是3且等级是0）

### 2.3 手动列表选择

```
格式：choose(表名(id1,id2,id3))+数量

示例：
choose(skills(21,22))+1      → 从技能[洞悉/医药]中选1个
choose(skills(27,29,30))+1   → 从技能[欺瞒/表演/游说]中选1个
choose(skills(12,26))+1      → 从技能[智力豁免/魅力豁免]中选1个
```

### 2.4 范围选择

```
格式：表名(id→id)

示例：
growup(303→322)              → 环位熟练表 id 303到322的范围
```

### 2.5 特殊操作

```
格式：操作名(参数)

示例：
all(skills)                  → 所有技能熟练
proficiency>pure             → 将某项熟练升级为专精
proficiency>pure+2           → 获得2个专精
proficiency>pure(11,12)+1    → 从奥秘/历史中选1个转为专精
half-prof(skills)            → 所有未熟练技能获得半熟练加值
half-prof(tools)             → 所有未熟练工具获得半熟练加值
spell_slot(lv=1)+1           → 额外1个1环法术位
```

### 2.6 多选一（选项标记）

```
格式：①表达式A,②表达式B,③表达式C

示例：
①feats(type=44)+1,②spells(class=3,lv=0)+2
→ 选项A：战斗风格专长选1个
→ 选项B：牧师戏法选2个

①spells(id=8),②spells(id=20)
→ 选项A：选择法术id=8
→ 选项B：选择法术id=20
```

### 2.7 属性/数值运算

```
格式：公式

示例：
AbilityModifiers(1)          → 力量调整值
lv:class(6)                  → 武僧等级
lv:class(1)*0.5>↓            → 野蛮人等级的一半，向下取整
Proficiency                  → 熟练加值
speed+10                     → 速度增加10尺
hp_per_lv+2                  → 每级额外2点生命值
1d10+lv:class(5)             → 1d10+战士等级
Character(不屈)               → 角色"不屈"资源计数
Character(不屈)+1             → "不屈"使用次数+1
```

### 2.8 前置条件

```
格式：prerequisite(条件)

示例：
prerequisite(lv:class(11)=2)     → 魔契师等级2
prerequisite(lv>=4)              → 等级≥4
prerequisite(ability(1)>=13)     → 力量≥13
prerequisite(feature(spellcasting)) → 具有施法特性
prerequisite(feature(pact_magic))   → 具有魔契魔法特性
```

### 2.9 连锁引用

```
格式：chain:特性id

示例：
chain:54                     → 引用同表中特性id=54的数据
```

### 2.10 代码标记

```
格式：code(标记)

示例：
code(choose)                 → 标记该行需要从①②③等选项中选择
code(二选一)                  → 标记需要在两个效果中选择一个
```

## 四、与旧引用表的映射

### 4.1 type=id → 直接引用

```
旧：link(1)    → source_table=feats, type=id, target_id=5
新：feats(id=5)  或  feats(name=魔法学徒)

旧：link(58)   → source_table=weapons, type=id, target_id=63
新：weapons(type=63)  或  weapons(name=简易武器)

旧：link(106)  → source_table=spells, type=id, target_id=56
新：spells(id=56)  或  spells(name=至圣斩)
```

### 4.2 type=type → 按类型筛选

```
旧：link(10)   → source_table=tools, type=type, target_id=66, count=1
新：tools(type=66)+1

旧：link(65)   → source_table=tools, type=type, target_id=67, count=3, complex_logic=choose
新：choose(tools(type=67))+3  或  tools(type=67)+3
```

### 4.3 type=filter → 条件筛选

```
旧：link(257)  → source_table=spells, type=filter, count=2, complex_logic="class=3,lv=0"
新：spells(class=3,lv=0)+2

旧：link(262)  → source_table=spells, type=filter, count=2, complex_logic="class=12,school=7"
新：spells(class=12,school=7)+2
```

### 4.4 type=choose → 手动列表

```
旧：link(187)  → source_table=skills, type=choose, count=1, complex_logic="21,22"
新：choose(skills(21,22))+1

旧：link(260)  → source_table=skills, type=choose, count=1, complex_logic="27,29,30"
新：choose(skills(27,29,30))+1
```

### 4.5 type=special → 特殊操作

```
旧：link(296)  → source_table=skills, type=special, complex_logic=all
新：all(skills)

旧：link(297)  → source_table=skills, type=special, count=1, complex_logic=proficiency>pure
新：proficiency>pure+1

旧：link(298)  → source_table=skills, type=special, complex_logic=half-prof
新：half-prof(skills)

旧：link(310)  → source_table=tools, type=special, count=1, complex_logic="choose(tool(type=66),tool(type=67))"
新：choose(tools(type=66),tools(type=67))+1
```

### 4.6 type=spell_slot → 法术位

```
旧：link(306)  → source_table=spell_slot, type=spell_slot, target_id=1, count=1
新：spell_slot(lv=1)+1
```

### 4.7 type=prerequisite → 前置条件

```
旧：link(506)  → source_table=basic, type=prerequisite, complex_logic="lv:class(11)=2"
新：prerequisite(lv:class(11)=2)

旧：link(520)  → source_table=basic, type=prerequisite, complex_logic="ability(1)>=13"
新：prerequisite(ability(1)>=13)
```

### 4.8 type=rules → 规则表达式

```
旧：link(514)  → source_table=basic, type=rules, complex_logic="Proficiency>pure+2"
新：Proficiency>pure+2

旧：link(309)  → source_table=basic, type=rules, complex_logic="hp_per_lv+2"
新：hp_per_lv+2
```

## 六、解析器设计

### 6.1 解析流程

```
输入表达式: "spells(class=3,lv=0)+2"
  ↓
Step 1: 正则匹配 → 表名="spells", 条件="class=3,lv=0", 数量="2"
  ↓
Step 2: 解析条件 → [{key:"class", value:"3"}, {key:"lv", value:"0"}]
  ↓
Step 3: 同一key多值拆分为OR → class=3 AND lv=0
  ↓
Step 4: 查目标表 → 从 spells.json 中筛选 class=3 且 lv=0 的条目
  ↓
Step 5: 返回结果 + 数量限制 → 返回前2个（或弹窗让用户选）
```

### 6.2 正则表达式

```javascript
// 基本引用: 表名(条件)+数量
const BASIC_REF = /^(\w+)\(([^)]+)\)(?:\+(\d+))?$/;

// 手动选择: choose(表名(id1,id2))+数量
const CHOOSE_REF = /^choose\((\w+)\(([^)]+)\)\)(?:\+(\d+))?$/;

// 多选一: ①表达式,②表达式
const MULTI_CHOICE = /^(①[^,]+)(,②[^,]+)(,③[^,]+)?$/;

// 属性调整值: AbilityModifiers(id)
const ABILITY_MOD = /AbilityModifiers\((\d+)\)/;

// 等级引用: lv:class(id)
const LV_REF = /lv:class\((\d+)\)/;
```

### 6.3 向后兼容

```javascript
function parseExpression(expr) {
  // 过渡期内，先检查是否是旧 link 语法
  if (expr.startsWith('link(')) {
    const id = expr.match(/link\((\d+)\)/)[1];
    // 查 legacy_lookup_table 转换为新表达式
    return legacyLookup(id);
  }
  
  // 新语法解析
  return parseNewExpression(expr);
}
```

## 七、给 AI 的填写指南

### 7.1 从规则文本提取的步骤

1. **识别引用目标**：这是专长？法术？技能？工具？
2. **确定表名**：对照"表名对照"章节
3. **确定条件**：
   - 如果是固定条目 → 用 `id=X` 或 `name=XXX`
   - 如果是筛选 → 用 `key=value` 条件
   - 如果是列表选择 → 用 `choose(表名(id1,id2))`
4. **确定数量**：需要选几个？默认 1 个
5. **输出表达式**

### 7.2 决策树

```
引用的是固定条目？
  ├─ 是 → 知道 id？
  │     ├─ 是 → 表名(id=X)
  │     └─ 否 → 表名(name=XXX)
  └─ 否 → 需要筛选？
        ├─ 是 → 有多个条件？
        │     ├─ 是 → 表名(key1=value1,key2=value2)+N
        │     └─ 否 → 表名(key=value)+N
        └─ 否 → 是手动列表？
              ├─ 是 → choose(表名(id1,id2,id3))+N
              └─ 否 → 是特殊操作？
                    ├─ 是 → all(表名) / proficiency>pure / half-prof(表名)
                    └─ 否 → 直接写公式（AbilityModifiers/hp/lv等）
```
