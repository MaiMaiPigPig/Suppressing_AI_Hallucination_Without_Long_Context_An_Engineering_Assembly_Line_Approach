# 00_通用约定

本文档适用于所有数据表。在填写任何 CSV 之前，请先读完本文档。

---

## 一、ID 分配规则

### 1.1 本体数据（DLC-0 / phb）
- ID 范围：**1 ~ 9999**
- 由核心团队维护，AI 不应修改

### 1.2 DLC 数据
- ID 范围：**10000 ~ 99999**
- 每个 DLC 在 `manifest.json` 中声明自己的 ID 前缀
- 示例：DLC "怪物图鉴" 前缀 = 10000，则它的数据 id = 10000, 10001, 10002...

### 1.3 覆盖规则
- DLC 可以用**相同 id** 覆盖本体的数据
- 示例：DLC 想修改"火球术"，使用 id=1（和本体相同），引擎优先读取 DLC 版本

### 1.4 预留 ID
- **0** 表示"无"或"全部"
- **负数** 保留给系统内部使用，DLC 不可用

## 二、CSV 格式规范

### 2.1 编码
- **UTF-8 without BOM**
- 分隔符：**英文逗号 `,`**
- 换行符：**CRLF**（Windows 默认）
- 文本中包含逗号时，必须用**双引号包裹**

### 2.2 空值处理
| 场景 | 写法 | 示例 |
|---|---|---|
| 数值为空 | 留空 | `1,名字,,描述`（第三列空） |
| 字符串为空 | 留空 | 同上 |
| 列表为空 | 留空 | 不是 `[]` 或 `""` |
| 布尔为 false | 0 | `0` |
| 布尔为 true | 1 | `1` |

### 2.3 列表格式
所有列表统一用**英文逗号分隔**，不要用中文顿号：

```
✅ 正确：10,12,13
❌ 错误：10、12、13
❌ 错误：[10,12,13]
```

### 2.4 文本中的换行
CSV 单元格内支持换行，必须用双引号包裹：

```csv
id,名字,详情
1,火球术,"第一行描述
第二行描述
第三行描述"
```

## 三、自描述表达式规范（v1.0 新增，替代 link(id)）

### 3.1 废除引用表
旧版使用 `link(id)` 引用中间表（引用表），存在以下问题：
- 魔法数字不可读（`link(58)` 不知道是什么）
- AI 填写困难（需要分配 ID、判断该不该放引用表）
- 和映射表职责重叠

**新版使用自描述表达式**，一看就懂，AI 可直接生成。

### 3.2 基本引用

```
格式：表名(条件)+数量

示例：
feats(id=5)              → 专长表 id=5 的条目
feats(name=魔法学徒)      → 专长表名字=魔法学徒的条目
spells(id=56)            → 法术表 id=56 的条目（至圣斩）
weapons(type=63)         → 武器表 type=63 的所有条目（简易武器）
skills(type=3)           → 技能表 type=3 的所有条目（技能类）
tools(type=66)           → 工具表 type=66 的所有条目（工匠工具）
```

### 3.3 多条件筛选

```
格式：表名(条件1,条件2,条件3)+数量

示例：
spells(class=3,lv=0)+2       → 牧师(class=3)的戏法(lv=0)中选2个
spells(class=12,school=11)+2 → 法师(class=12)塑能学派(school=11)法术选2个
spells(lv=1,school=9,10)+1   → 1环预言/惑控法术选1个
weapons(category=63,64)+1    → 简易或军用武器选1个
```

**条件连接规则**：
- 同一条件多次出现 = OR（如 `school=9,10` = 学派是9或10）
- 不同条件 = AND（如 `class=3,lv=0` = 职业是3且等级是0）

### 3.4 手动列表选择

```
格式：choose(表名(id1,id2,id3))+数量

示例：
choose(skills(21,22))+1      → 从技能[洞悉/医药]中选1个
choose(skills(27,29,30))+1   → 从技能[欺瞒/表演/游说]中选1个
choose(skills(12,26))+1      → 从技能[智力豁免/魅力豁免]中选1个
```

### 3.5 范围选择

```
格式：表名(id→id)

示例：
growup(303→322)              → 环位熟练表 id 303到322的范围
```

### 3.6 特殊操作

```
格式：操作名(参数)

示例：
all(skills)                  → 所有技能熟练
proficiency>pure             → 将某项熟练升级为专精
proficiency>pure+2           → 获得2个专精
proficiency>pure(11,12)+1    → 从奥秘/历史中选1个转为专精
half-prof(skills)            → 所有未熟练技能获得半熟练加值
half-prof(tools)             → 所有未熟练工具获得半熟练加值
spell_slot(lv=1)+1           → 额外1个1环法术位
```

### 3.7 多选一（选项标记）

```
格式：①表达式A,②表达式B,③表达式C

示例：
①feats(type=44)+1,②spells(class=3,lv=0)+2
→ 选项A：战斗风格专长选1个
→ 选项B：牧师戏法选2个

①spells(id=8),②spells(id=20)
→ 选项A：选择法术id=8
→ 选项B：选择法术id=20
```

### 3.8 属性/数值运算

```
格式：公式

示例：
AbilityModifiers(1)          → 力量调整值
lv:class(6)                  → 武僧等级
lv:class(1)*0.5>↓            → 野蛮人等级的一半，向下取整
Proficiency                  → 熟练加值
speed+10                     → 速度增加10尺
hp_per_lv+2                  → 每级额外2点生命值
1d10+lv:class(5)             → 1d10+战士等级
Character(不屈)               → 角色"不屈"资源计数
Character(不屈)+1             → "不屈"使用次数+1
```

### 3.9 前置条件

```
格式：prerequisite(条件)

示例：
prerequisite(lv:class(11)=2)     → 魔契师等级2
prerequisite(lv>=4)              → 等级≥4
prerequisite(ability(1)>=13)     → 力量≥13
prerequisite(feature(spellcasting)) → 具有施法特性
prerequisite(feature(pact_magic))   → 具有魔契魔法特性
```

### 3.10 连锁引用

```
格式：chain:特性id

示例：
chain:54                     → 引用同表中特性id=54的数据
```

### 3.11 代码标记

```
格式：code(标记)

示例：
code(choose)                 → 标记该行需要从①②③等选项中选择
code(二选一)                  → 标记需要在两个效果中选择一个
```

## 五、向后兼容（过渡期内）

旧版 `link(id)` 语法在过渡期内继续支持：

```javascript
function parseExpression(expr) {
  // 过渡期内，先检查是否是旧 link 语法
  if (expr.startsWith('link(')) {
    const id = expr.match(/link\((\d+)\)/)[1];
    // 查 legacy_lookup_table 转换为新表达式
    return legacyLookup(id);
  }
  
  // 新语法解析
  return parseNewExpression(expr);
}
```

过渡期：自 v1.0.0 发布起 3 个月。
过渡期结束后，`link(id)` 语法正式废弃。

## 六、字段命名约定

### 6.1 列名语言
- **CSV 文件**：使用中文列名（方便人类阅读）
- **JSON 输出**：自动转换为英文列名（方便代码使用）
- 转换规则见 `csv转json.py` 中的 `KEY_MAP`

### 6.2 新增字段命名
如果你给某个表新增字段：
1. 中文名要**自描述**，不要缩写
2. 英文名用**snake_case**
3. 在 Schema 文档中补充该字段的说明

## 七、DLC 数据包结构

每个 DLC 必须包含以下文件：

```
dlc_{编号}_{名称}/
├── manifest.json          ← DLC 元数据（必须）
├── schema/                ← 本 DLC 特有的 Schema 说明（可选）
│   └── 法术_扩展.md       ← 只写和本体不同的地方
└── csv/                   ← 数据文件（必须）
    ├── 法术.csv           ← 只包含本 DLC 新增/覆盖的数据
    └── 种族特性.csv
```

### 7.1 manifest.json 格式

```json
{
  "id": "dlc_01",
  "name": "剑湾冒险者指南",
  "version": "1.0.0",
  "depends_on": ["phb"],
  "author": "AI 生成 / 玩家社区",
  "description": "新增了 3 个种族和 15 个法术",
  "tables": {
    "新增": ["races", "race_features", "spells"],
    "覆盖": []
  },
  "id_prefix": 10000,
  "compatibility": {
    "min_engine_version": "0.5.0",
    "max_engine_version": "1.0.0"
  }
}
```

### 7.2 DLC 加载顺序
1. 引擎先加载本体（DLC-0 / phb）
2. 按 `depends_on` 声明的顺序加载依赖 DLC
3. 最后加载当前 DLC
4. 相同 id 的数据，**后加载的覆盖先加载的**

## 八、数据校验规则

### 8.1 AI 自检清单（填写完必须检查）

```
□ ID 是否在本 DLC 分配范围内？
□ 所有必填字段是否已填写？
□ 引用的 ID 是否存在于目标表？
□ 列表是否使用英文逗号分隔？
□ 文本中的逗号是否用双引号包裹？
□ 数值字段是否没有混入文本？
□ 是否有和本体重复的 id（如果是覆盖，确认是故意的）？
□ 是否使用了自描述表达式（而非旧的 link(id)）？
```

### 8.2 引擎校验（运行时）
- 加载数据时检查所有外键引用是否存在
- 发现 broken link 时记录警告，使用默认值或跳过
- 版本不匹配时拒绝加载 DLC

## 九、版本管理

### 9.1 数据版本
每次修改数据后，更新 `manifest.json` 中的 `version`：

```
1.0.0 → 1.0.1  （修复错误）
1.0.0 → 1.1.0  （新增内容）
1.0.0 → 2.0.0  （不兼容变更）
```

### 9.2 Schema 版本
Schema 文档本身的版本在 `README.md` 中声明。
Schema 升级时：
- 小版本更新（v0.1 → v0.2）：新增字段，旧数据兼容
- 大版本更新（v0.x → v1.0）：可能修改字段含义，需要迁移脚本

### 9.3 字段状态标记
每个 Schema 文档中的字段都有状态标记：

| 标记 | 含义 | 说明 |
|---|---|---|
| ✅ | 已支持 | 当前版本已实现，可正常使用 |
| ⏳ | 开发中 | 正在开发，可能不完整 |
| 📋 | 计划中 | 已设计但尚未实现 |

## 十、AI 填写决策树

当 AI 从规则文本提取数据时，按以下决策树选择表达式类型：

```
引用的是固定条目？
  ├─ 是 → 知道 id？
  │     ├─ 是 → 表名(id=X)
  │     └─ 否 → 表名(name=XXX)
  └─ 否 → 需要筛选？
        ├─ 是 → 有多个条件？
        │     ├─ 是 → 表名(key1=value1,key2=value2)+N
        │     └─ 否 → 表名(key=value)+N
        └─ 否 → 是手动列表？
              ├─ 是 → choose(表名(id1,id2,id3))+N
              └─ 否 → 是特殊操作？
                    ├─ 是 → all(表名) / proficiency>pure / half-prof(表名)
                    └─ 否 → 直接写公式（AbilityModifiers/hp/lv等）
```
